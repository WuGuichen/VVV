## CharacterTest Deterministic Gameplay Sync (2026-06-11)

### Fixed assembly optional state projection (2026-10-11)

CharacterTest snapshot capture now emits wire schema **41**. The optional `fixedAssemblyState` fragment contains the actual actor runtime/index/generation, complete interaction/accessory state, the World-bound momentum ledger (`Current`, `Reserved`, `NextToken`, `ActiveToken`) and a digest of the trusted confirmed manifest view. It is absent for ordinary empty assembly state. Schema 40 without this extension remains an accepted format. Ordinary import requires no live fixed assembly state and no actual World-bound `MomentumLedger`; the bounded private paused owner can still restore a legacy empty assembly using its separate complete `Motion` fragment. Rollback clones copy the extension and every mutable nested value.

Full, owned and non-owned production hashes share `AddCharacterEntityHash`: each actor with an actual World-bound `MomentumLedger` or fixed assembly state contributes its existing interaction fields **325–356**, ledger presence/state **357–361**, confirmed manifest format/order/restoration/digests **362–365**, and journal presence **366**. These are registered character fields under the existing NetworkSnapshot schema 1003/version 1, with no new contributor. The predicate belongs to each actor; adding another actor's journal cannot change an excluded actor's hash layout. A defending actor's real ledger is covered even without accessories. The absent wire extension does not disable ledger hashing; the schema-41 protocol scalar also changes the ordinary snapshot hash. Immutable publication digests are prepared cold; the live hash reads the actual ledger without snapshot serialization/allocation.

The transported digest never creates an admission authority. The private paused-session owner can import this fragment only against a witness frozen from its original complete frame, known confirmed records, deck/card identities and actual resource bindings; it then restores deck, ledgers and effects on an unpublished fresh candidate. Rehashed changes to consumption, receipts, card versions, resource values, owner identities or the complete extension are rejected against that witness. Repeated restoration loads the same states without new payment, arming or motion publication. Confirmed manifest promotion is still a parameter operation: it is not an implemented joint payment transaction or a compiler-proven action budget.

The private paused-session envelope additionally carries an optional idle execution history: actual settlement retires the active ID while preserving the last admitted card/version, mode-specific terminal facts, reward deduplication history and allocator high-water mark. A frozen live context checks this history and its deck before creating a candidate. Missing history is compatible only with a context that never admitted an execution. Restore loads historical facts without restarting a host, replaying payment/refund or reusing IDs. This bounded codec still requires an actually idle action/world; a Planning pause during free recovery remains outside its capability. These private history fields are covered by its complete content digest, not exposed as a new general network restore authority.

Ordinary network import, service rollback, transport correction and replay gameplay bootstrap cannot restore a known live World-bound `MomentumLedger` or P2 state until the actual ledger, trusted journal and same-frame deck have an aggregate restore owner. Snapshot apply and direct character restore reject this extension or either live authority, including ledger-only actors with no accessories; service rollback and transport correction run the carrier/document guard before changing the clock, and replay gameplay bootstrap runs it before `AdvanceToFrame` can tick the world. Ledger-only rejection reports `network:MomentumLedgerAggregateRestoreUnavailable` with an explicit explanation that an aggregate ledger/deck restore owner is required; P2 still reports `network:FixedAssemblyAggregateRestoreUnavailable`. This does not make session-authority factory/reset or unrelated provider failures transactional. Ledger-only capture still omits the optional network fragment, so a fresh receiver cannot identify omitted source ledger authority from that fragment's absence. The private paused owner restores the actual ledger through its separate `Motion` fragment on a fresh candidate; this is not generic network rollback support. Existing later provider apply paths are not claimed to be fully transactional. Explicit fixture parameters verify these boundaries; no formal accessory/default fee/lifetime content was published. Development scope and remaining execution-owner boundary are recorded in [the assembly plan](../Plans/TacticalCardAssemblyDevelopmentPlan.md#35-暂停恢复与生产hash复用计划2026-10-11实施前).

CharacterTest Host/Join defaults to `NetworkStateSyncPolicy.BootstrapOnly`: during gameplay the only replicated state-changing stream is the server-accepted `NetworkAuthoritativeCommandPacket`, and every endpoint advances movement, animation, and action state through the same fixed-frame `RuntimeCommandBuffer`. Regular digest snapshots, hash-mismatch full snapshot requests, and late-command full snapshot fallback are disabled for the player-facing CharacterTest LAN flow.

`BootstrapOnly` still allows a reliable full snapshot for connection/bootstrap so optional entity-control grants and initial state setup keep working. A connected peer may intentionally remain unbound. After local gameplay entry, Sync Probe and MPPM automation expect full snapshot delta, digest snapshot delta, and snapshot request delta to remain `0`; growth in any of them is reported as `STATE_SYNC_ACTIVE`.

The framework-compatible `NetworkStateSyncPolicy.SnapshotVerification` remains available for callers that still want digest/full snapshot verification. `NetworkSessionConfig` now carries `StateSyncPolicy` and independent `HeartbeatIntervalFrames`; ping/pong no longer uses snapshot interval, and authoritative command lead / client prediction lead no longer include snapshot cadence.

CharacterTest server-side replay records the same server-accepted, server-scheduled authoritative command stream that is broadcast to clients. `NetworkSessionRunner` exposes this stream through an optional `NetworkAuthoritativeCommandPacket` observer; CharacterTest server/host runners feed it into `CharacterTestReplayRecorder` exactly once per accepted packet, before receiver fanout. Client prediction and host-local client echo are not recorded as replay truth.

`MxFramework.Network` now exposes noEngine prediction rollback primitives for gameplay clients that keep a local memory history: `INetworkRollbackParticipant` captures/restores module state, `NetworkPredictionRollbackCoordinator` owns a bounded frame history (default 128 frames) plus predicted/authoritative command ledgers, and `NetworkSessionRunner` can delegate authoritative-command and full-snapshot correction to caller-provided hooks before the legacy late-drop/resync path runs. `RuntimeCommandBufferSnapshot` lets replay restore command buffer state without bypassing normal command validation. CharacterTest is the first integration: late authoritative commands restore the affected state, replace or enqueue authoritative input, and replay fixed ticks to the current local frame; full snapshot corrections restore the authoritative snapshot and then replay locally retained predicted commands. This does not change the wire protocol.

`CharacterTestReplayFrameDriver` replays a capture in EditMode by creating a clean headless `GameSlice`, applying the bootstrap snapshot baseline, injecting recorded `RuntimeCommand[]` for each recorded frame, ticking the slice, and comparing `CharacterTestNetworkSnapshotParticipant.ComputeStateHash(...)` with the recorded result hash. This is a diagnostic/test replay, not a player-facing replay UI or long-term save format.

## CharacterTest NetworkPanel Ready Room Semantics (2026-06-10)

Player-facing CharacterTest Host means "start authoritative LAN server and join it locally as the host player." `CharacterTestNetworkSessionKind.Host + Room` maps to `UnityTransportRoomHost`; `Host + DirectLan` maps to `UnityTransportHost`; server-only runners remain internal/development plumbing.

Composer-owned `MxCharacterTestNetworkUi/NetworkPanel` defaults to LAN Room, uses a full-screen lobby layout, and remains open after Host/Join. Room mode disables panel-started `RoomClientAutoReady` and `RoomServerAutoStartWhenReady`: each player manually sends `SetReady`; after the ready gate passes, only Host can click `Enter Game`. Host `Enter Game` calls the existing room `TryStartGame` path, then Host and Clients close NetworkPanel/MainMenu automatically after room `InGame`, gameplay client connected, owned entity assigned, and first full snapshot received locally. During the room gameplay handshake, clients keep the gameplay slice on the fixed tick so client command frames stay aligned with the server; local control submissions before server authority are silently ignored and not sent as gameplay commands. Direct LAN has no ready protocol and enables local `Enter Game` only after connected + owned entity + full snapshot. While a session is active, the panel keeps network ticking under UI exclusive input and `Back` is disabled in favor of `Disconnect`.

After gameplay verification, NetworkPanel can run `Run Sync Probe` as a local diagnostic. The panel also has a persisted local `Auto Probe` trigger: when enabled before `Enter Game`, `GameManager` starts the same probe automatically after this instance completes local gameplay entry. The probe does not add network protocol state or host broadcast semantics; it injects a fixed `MoveStopLoop` `SetControlIntent` script through `GameSlice.EnqueueRuntimeCommand()` for 15 seconds / 900 network frames and samples `CharacterTestNetworkLoopbackDiagnostics` to classify auth command late/drop/no echo, missing stop intent, full snapshot growth, transport backlog, frame drift, and command-vs-snapshot byte ratios. Final reports are logged to Unity Console, retained in NetworkPanel diagnostics when reopened, and written as per-frame JSONL under `Application.persistentDataPath/MxFramework/CharacterTest/SyncProbe/`. When the local runner exposes authoritative replay, the same panel shows `Replay Check` status beside the probe summary; clients without replay show `host only`.

`CharacterTestNetworkAutomationRequest` / `CharacterTestNetworkAutomationRunner` provide the framework-level automated MPPM smoke path. A PlayMode test writes a short-lived shared request to `PlayerPrefs` and `Application.persistentDataPath/CharacterTest/NetworkAutomation`; each running player loads it on `GameManager.OnEnable`. `Unity.Multiplayer.Playmode.CurrentPlayer` is accessed by reflection so CharacterTest runtime does not hard-depend on MPPM assemblies: Main Editor becomes Host, Virtual Players become Join clients. The runner only calls the existing `GameManager` session/lobby/diagnostic interfaces: Host/Join, SetReady, Host Enter Game, local gameplay enter after `RoomStatus=InGame + CanEnterGameplay`, and Sync Probe. Sync Probe starts a host-side authoritative replay recording when the active runner exposes `ICharacterTestNetworkReplayRunner`; after the probe completes, Host validates the capture locally and writes replay status into the automation report. Each instance writes an atomic JSON `CharacterTestNetworkAutomationReport` with role, peer id, owned entity, room counts, auth command counters, late/drop/full snapshot/snapshot request/frame drift, wire bytes, Sync Probe result, and replay result fields. The main PlayMode test waits for Host + Client reports and then exits PlayMode. v1 requires the user or Unity MCP to select an MPPM Scenario with Main Editor Player plus at least 1 Virtual Player; it intentionally does not call internal MPPM ScenarioRunner APIs.

`MxFramework.Network` 是 noEngine、传输无关、服务端权威的网络抽象。当前分为两层：`NetworkRoomSessionRunner` 负责 gameplay 前的 LAN room 编排（join / ready / start / handoff），`NetworkSessionRunner` 负责进入 gameplay 后的 command、snapshot、hash 校验和 resync。网络连接只建立 Peer 会话身份，不隐含角色生成或实体所有权；CharacterTest 可按具体玩法附加 server-authoritative entity-control grant，只有获得 grant 的 client 才预测对应 entity。Phase 19.4B另以additive protocol-2 bounded packet seam支持caller-owned binary wire、atomic frontiers、ordered state participants和preallocated rollback history；legacy protocol-1 JSON路径保持兼容。

`NetworkSessionRunner.CopyConnectedPeerIdsTo(List<string>)` 向 caller-owned list 追加当前连接 ID；调用方控制清空与容量。内部直接枚举连接集合，避免经 `IReadOnlyCollection` 枚举而装箱；顺序与既有连接集合一致。

## 边界

- `MxFramework.Network` 只依赖 `MxFramework.Runtime`，`MxFramework.Network.asmdef` 保持 `noEngineReferences=true`。
- 网络核心不引用 Unity、Unity Transport、WebSocket、CharacterTest、Gameplay 私有字段或资源加载实现。
- `INetworkTransport` 只负责 message send / poll、transport event poll 和 diagnostics，不理解 gameplay payload。
- 物品库存同步通过可选 `MxFramework.Items.Network` bridge 接入；Network core 只看到 compact `RuntimeCommand`、`INetworkSnapshotParticipant`、`INetworkRollbackParticipant` 和 command authorizer，不读取 item catalog、profile、resource key 或 SaveState JSON。
- Gameplay Trigger network authority通过可选`MxFramework.Gameplay.Triggers.NetworkBridge` sibling assembly接入；Network core只看到bounded packet ingress、state/rollback participant和numeric profile hash，不反向引用Gameplay/Trigger catalog、entity或component类型。
- Room Session 是 gameplay session 上层编排，只处理 member、ready、start 和 handoff；不处理角色归属、输入同步、snapshot、预测或 rollback。
- Unity Transport 适配位于独立 Unity-facing 程序集 `MxFramework.Network.UnityTransport`；当前提供 object loopback、codec-backed byte loopback、Unity Transport loopback 和 CharacterTest UTP server/client 单端入口，用于测试、CharacterTest 本机场景验证和 LAN 双实例手测；adapter 已包含 MVP 断线事件、同 peerId 重握手、client transport restart、driver update failure 恢复和 receive/send queue capacity 配置。
- MVP 使用 fixed tick command + digest snapshot 校验 + full snapshot resync；Network core 提供通用 prediction rollback 协调器和 runner correction hooks，CharacterTest remote client 已接入 authoritative command / full snapshot live rollback。生产级视觉误差平滑、认证 token、房间恢复、角色恢复和协议级可靠重传仍不属于当前切片。
- `RemoteBundleProvider` 属于 Resources 资源分发，不属于 gameplay session 网络。
- Animation presentation sync 只消费项目网络层提供的权威表现状态，不拥有同步协议或 session authority。

## Wire / Transport Contract

- legacy protocol-1 wire envelope schema v0 固定包含 session、sender、receiver、sequence、channel、kind、runtime frame 和 payload。
- Payload 按 `NetworkMessageKind` 显式分发；正式 payload 实现 `INetworkMessagePayload`，runner 用 `TryGetPayload<T>()` 强类型取包；payload type mismatch、unknown kind、bad JSON、schema mismatch 返回 `NetworkCodecError` 并进入 diagnostics。
- protocol-2 kinds 10..13不走JSON envelope：outer固定52 B，magic `0x4D584E31`、schema 1、flags/reserved必须0，CRC32按CRC字段清零后的完整packet计算。command/snapshot total limit分别8192/524288 B；packet使用numeric session/peer handle、signed frame/sequence和caller-owned Span。
- protocol-2必须exact 2↔2并匹配bounded capability/profile hash；protocol 1拒绝kinds 10..13，protocol 2失败不silent downgrade。`outerSequence`跨四种kind共享per-session/per-direction frontier，各payload semantic sequence独立；decode/auth/capacity/candidate/admission任一失败都不推进frontier。
- CRC32只校验误码/完整性，不认证sender。bounded transport/session必须把authenticated session、remote sender、local receiver和direction作为独立metadata返回；loopback send/test seam也单独存储该metadata，不从packet解码推导receiver或sender。
- `NetworkSessionRunner`只在`Connected`状态接收bounded packet，并先精确核对configured session/local、authenticated metadata、header session/sender/receiver以及kind-direction-role矩阵；任一不一致在调用ingress前拒绝。上层authority/snapshot ingress只使用authenticated context做peer/ownership/server身份判断。Network core仍不存储credential、不加密、不建立account或matchmaking事实。
- `ReliableOrdered` v1 由传输适配保证可靠有序；Network core 做 sequence 诊断、重复包丢弃、乱序 / gap 记录，不实现重传或 fragmentation。prediction rollback 是 session/runner 上层的本地状态恢复与 replay primitive，不改变 wire protocol。
- `Unreliable` 允许乱序 / 丢包，默认只用于 regular digest snapshot；gameplay command、handshake、snapshot request 和 full snapshot 继续走 reliable ordered。
- Room command/state 走 `ReliableOrdered`；server 每次接受或拒绝 room mutation 都下发 full room state，不做 delta、外部 discovery、认证 token 或房间层重传。
- Application control request/response 走 `ReliableOrdered`，只承载组合根拥有的低频 typed session mutation。UTP 接收端在连接首次携带非空 sender 时建立不可重绑定的 connection-to-peer identity，后续 envelope sender 不一致或重复占用同一 peer id 会断开该连接；`NetworkSessionRunner` 只把已完成 handshake 的 connected peer 交给 application handler。Network core 不解析 application payload，也不允许用该入口上传 runtime profile、行为逻辑 JSON 或其它逐帧 gameplay 数据；具体 schema、大小上限、ownership 和 catalog 校验由 application handler 负责。生产认证 token 仍属于后续产品接入，不由当前首次绑定合同替代。
- `NetworkTransportSnapshot` 记录 pending、sent、delivered、dropped、reordered、codec error、sent/delivered bytes、last/max payload bytes 和按消息类型分桶的 sent bytes（含 room bytes）；`NetworkSessionRunner` 记录 smoothed rtt、avg/max rtt、snapshot interval、server/client frame drift、duplicate、out-of-order、disconnect reason、comparable/missing hash、snapshot request 和 full/digest snapshot count。
- `ReliableOrdered` 的 command ack 按 input peer 记录；server 广播 snapshot 时为每个接收 peer 写入自己的 `AckedInputFrame`，避免多 client 之间 ack 互相污染。
- `ReliableOrdered` command packet 到达 server 后可先经过组合根提供的 command authorizer；拒绝的 command 不写入 `RuntimeCommandBuffer`，不更新该 peer ack，并进入 structured diagnostics。
- Items bridge 使用这一 hook 拒绝 client-origin `AddStack` / `RemoveStack`、跨 owner/container 操作和 malformed compact inventory command；允许的库存命令仍作为 server authoritative command stream 广播。
- Full snapshot capture 可按 receiver peer id 个性化；digest snapshot 仍不携带模块状态，但 result hash 可由 server 按 receiver peer id 计算，便于 client 只比较自己预测过的 owned state。

## 恢复状态与历史边界（2026-10-08）

`NetworkSessionStatus.Resynchronizing` 表示 authority admission 已暂停，等待完整状态；`RecoveryFailed` 表示不能安全继续，必须由调用者明确重连或重建会话。`IsAuthorityReady` 仅在 Connected 为 true。CharacterTest remote client 和 loopback mirror 在这两种状态停止 authority Tick，remote client 不自动重连；网络收包与恢复冷却仍按网络帧推进。

缺失已过去帧的 hash history 不计为 hash mismatch，但 SnapshotVerification 会立即进入 Resynchronizing 并沿现有 SnapshotRequest 请求 full state；丢失回复后按 snapshotRequestCooldownFrames 重试（最少隔一个网络帧）。迟到权威命令无法 replay 时执行同一恢复契约。BootstrapOnly 保持原有无自动 snapshot request 策略并进入 RecoveryFailed；明确 Connect 后必须完成新握手并收到完整 bootstrap 才解除暂停。上述恢复策略沿用wire protocol 1／2；当前CharacterTest snapshot capture schema为41，旧40空P2投影兼容边界见本文固定装配状态段。

完整 snapshot 必须含每个已注册 participant 恰好一次，缺失、重复、未知模块在发布前拒绝；组合方须注册与服务端相同的恢复模块。callback 的 HandledApplied 仍由应用层负责实际完整恢复。任何 Apply/HandledFailed 不再算成功，legacy participant 若已部分应用则保持 RecoveryFailed，不能通过重复 apply 声称原子恢复；多 participant 原子发布使用既有 bounded prepare/commit seam。

恢复期 authoritative-command hook 必须只保留命令并返回 handled；没有保留能力的 handler/legacy 路径失败停止。CharacterTest remote client 通过 RecordAuthoritativeCommand 保留 ledger，full restore 从恢复帧开始重新建立 history，丢弃已被 full state 覆盖的旧命令与旧 checkpoints，保留未来命令。重演同帧 checkpoint 替换旧槽，避免二次纠偏读取旧状态。相同 frame/hash/modules 的重复 full state 与更旧 full state不再重复应用；同帧但内容不同的合法更新仍可应用。断开清空 deferred snapshots，明确重连重新握手并等待完整状态，不能用握手成功代替恢复成功。

实际纯逻辑回归：NetworkSessionRunnerTests 的 Recovery_* 使用生产 runner/coordinator、Loopback transport 与 RuntimeCommandBuffer；真实 GameSlice 回归入口为 CharacterTestNetworkLoopbackTests.RemoteClient_ExhaustedProductionHistoryStopsAuthorityWithoutAutomaticReconnect。后者必须由唯一 Unity owner 执行，不以纯逻辑结果替代。
