## 职责与边界

`MxFramework.Gameplay.Triggers` 是独立的纯 C# Gameplay 规则模块，依赖 `MxFramework.Core`、`MxFramework.Runtime` 和 `MxFramework.Gameplay`，`noEngineReferences=true`。它把 complete occupancy、complete scalar sample 或 typed Signal 归约为稳定 occurrence，再执行 Route 的只读 condition、activation policy、exclusive arbitration 和 reservation-based action dispatch。

- 可打开入口固定为 `Assets/Scenes/GameplayTriggerPlayable.unity`；Unity菜单 `MxFramework/Gameplay Triggers/Create Playable Scene` 负责受控重建场景。
- `GameplayTriggerPlayableSession` / composition复用正式 `RuntimeHost`、Combat motion/physics occupancy、Trigger systems、Gameplay Buff bridge、Story reliable bridge、Runtime checkpoint barrier、SaveState participants和canonical authority hash；Unity primitives与UI Toolkit只投影视图和validation controls。
- checkpoint Entered先通过Trigger-owned deferred action启用door binding；door Entered经reliable Story `RaiseTrigger`在后续帧打开门；trap Entered/Stayed经same-frame Gameplay Buff bridge累计counter并刷新slow。
- 键盘 `WASD`/方向键移动，`E` Capture，`F6` Restore，`F4` Reset；HUD提供对应方向held/pulse与`CAPTURE / RESTORE / RESET`按钮，并显示Frame、位置、checkpoint/door/trap、event/result、authority hash和capture状态。
- Capture只在checkpoint已获得且最新Tick完整成功、quiescent时，把`RuntimeSaveState`保存到当前session的单个内存slot；Restore在fresh candidate composition中prepare/restore/verify后原子换入；Reset发布fresh default composition并清空slot。该slot不写磁盘、不经过profile/store，不是durable persistence。
- deterministic input trace与capture后suffix的canonical hash一致，证明本地SaveState/replay-compatible authority组合；Playable本身仍不提供replay timeline或network UI。19.4B由独立noEngine/network harness交付，不改变该场景的功能边界。

## Phase 19.4B Network / Scale 契约

- protocol 2 是显式 opt-in 且 exact-match；`NetworkMessageKind` 10/11/12/13 分别为 bounded client commands、authoritative commands、state snapshot、state request。protocol 1 legacy JSON 路径保持兼容，但不能自动降级，也不能接收 kinds 10..13。
- outer packet 固定 52 B，magic `0x4D584E31`、wire schema 1、CRC32 以 CRC 字段清零后覆盖完整 packet。command total 上限 8192 B，snapshot total 上限 524288 B，单 command packet最多64条；fixed command record 116 B且不编码 `TraceId`，runtime/authoritative/snapshot/request payload header分别为104/120/124/56 B。
- transport/session接收必须在packet bytes之外独立返回authenticated session、remote sender、local receiver和direction；runner先要求session处于Connected，再精确核对本地配置、transport metadata与packet header。CRC32只校验误码/完整性，不提供身份认证。authority/snapshot ingress只使用`NetworkBoundedIngressContext`里的authenticated remote做connected peer、ownership和server身份判断，包头sender不能覆盖该事实。
- `outerSequence` 是同一 authenticated session、同方向、跨 kinds 10..13 的唯一 anti-replay frontier；client command、authoritative command、snapshot id、state request各有独立 semantic frontier。所有 applicable frontier 与 profile/catalog/auth/ownership/capacity/candidate admission 一起原子推进，失败不改变 pending、frame、sequence或authority。
- `GameplayTriggerNetworkProfile` schema 1 固定三项 Trigger catalog hash、十二项 runtime capacity option、command source policy、外部提供的 canonical `NetworkProfileHash` 和 `FullComparable` / `PartialNonComparable`。client只允许注入 profile allowlist 内的 Exogenous typed observation，且必须绑定已连接 authenticated remote peer和其 owned subject。raw lifecycle/control/action/result、Derived forgery、unknown source/profile/schema/peer及错误 owner都在 authority mutation 前拒绝。
- `GameplayTriggerNetworkStateBundle` 固定 Gameplay participant type `1002301`、restore order 100，Trigger participant type `1002302`、order 200。FullComparable composition必须为每个已注册 Gameplay component CLR store显式提供一个 `IGameplayComponentNetworkStateCodec`，本地精确比对 type set，wire再校验稳定 numeric TypeId/schema/order/offset/length/capacity；任一 missing/duplicate/extra/wrong type或candidate mismatch都在 live publication 前失败。发布阶段沿用现有 Gameplay lifecycle restore，为 `LowFreqAlloc`；steady capture/prepare/discard为初始化后 `NoAlloc`。
- end-of-F snapshot恢复到F，首个合法 Tick为F+1；fresh late join与不中断 baseline逐帧收敛。参与预测的 client用`GameplayTriggerNetworkRollbackResync`和existing `NetworkPredictionRollbackCoordinator`记录bounded Gameplay+Trigger history并回滚/重放。rollback record先把完整frame写入预分配scratch，全部participant capture成功后才覆盖ring slot并推进history；restore先prepare全部participant，再按`RestoreOrder -> TypeId`执行no-fail commit（Gameplay 100 -> Trigger 200），任一prepare失败则对全部participant幂等discard并保持全部live state不变。不运行完整 Trigger composition的client必须声明`PartialNonComparable`，不得比较full-world hash。缺 history、hash mismatch、catalog/schema/corrupt/unauthorized snapshot或restore失败进入typed bounded resync；重复但byte-identical snapshot幂等。
- 固定seed `0x0739194B` 的规模档为64 definitions、256 instances、2048 active relations、每帧64 signals/512 candidates/256 actions（128 same-frame + 128 reliable）、128-frame rollback history、2 participants；120帧预热后测480帧。Apple M4/16 GB、macOS 26.5.1、Unity 6000.5.0f1 BatchMode结果：median 1.519100 ms、P95 1.569100 ms、max 1.613900 ms；Trigger-owned 0 B、bounded wire+rollback 0 B、infrastructure 0 B、managed heap peak delta 0 B；snapshot 132752 B。全部低于冻结的4/6/10 ms、1 MiB infrastructure、4 MiB heap和512 KiB snapshot预算。
- 当前不包含transport encryption、credential/account、matchmaking、Relay、lobby UI、durable persistence、CharacterTest protocol migration、generic Unity action bridge、JSON importer或active-session hot reload。

## Presentation Event Router 契约

CharacterTest T4-D 增加项目专用 BattleVitals Signal 来源（provider 3、SignalId 450501、schema 1）：每个 StageRun 从原 roster 复制同帧双方 HP，使用 unordered complete batch；胜败互斥条件及一次性可靠 RaiseTrigger/事务关闭双方绑定继续由本模块执行。帧末交接读取 intent/outbox 与直接 Story result sink，observer 不承担结算权威。该 Runtime 接入不把通用 Signal 编排开放为现有 Editor 工作区能力；源合同、会话装配与验收范围见 [CharacterTest.TacticalCard](CharacterTest.TacticalCard.md#t4-d-胜负与-story-交接)。

稳定数值定义：kind 为 `None=0`、`Occurrence=1`、`ActivationAccepted=2`、`ActionDispatched=3`、`RuntimeDiagnostic=4`、`CommandResult=5`、`InternalDeferredResult=6`、`ReliableTransferResult=7`、`ActionResult=8`；status 为 `None=0`、`Observed=1`、`Accepted=2`、`Dispatched=3`、`Succeeded=4`、`Rejected=5`、`Retained=6`；drop reason 为 `None=0`、`SourceCapacityExceeded=1`、`SourceSequenceExhausted=2`、`ObserverCapacityExceeded=3`、`ObserverDisabled=4`、`InvalidActionResult=5`。

payload 是一个 flat readonly value：公共 header 为 `Frame / SourceSequence / Kind / Status`；origin identity 为 `DefinitionId / BindingId / SourceBindingId / InstanceId / RouteId / ActivationId / Owner`；occurrence block 为 `Subject / Instigator / OccurrenceKind / SignalId / PreviousScalarRaw / CurrentScalarRaw / OccurrencePayload0..2 / OrderingValue / PresenceEpoch / PresenceStartFrame`；action block 为 `ActionIndex / ActionKindId / Target / ActionPayload0..2`；时序 block 为 `OriginFrame / DueFrame / ProducerSequence`；deferred/reliable block 为 `TargetInstanceId / TargetSourceBindingId / InternalDeferredOperationKind / ReliableTransferStatus`；command block 为 `RuntimeCommandKind / CommandSourceId / CommandId / CommandTargetId / CommandPayload0..2 / Provenance / BatchId`；result block 为 `ReasonCode / Detail0..1 / ResultPayload0..2`。event 内不含 string、object、delegate、Unity identity、sink/transfer reference 或隐藏引用字段。

| producer | exact publish 点 | `OriginFrame / DueFrame / ProducerSequence` | 关键字段 |
| --- | --- | --- | --- |
| canonical occurrence | 全部 occurrence 完成 canonical sort/ordinal 后 | occurrence frame / default / `0` | static origin + 完整 occurrence；`ActionIndex=-1` |
| accepted activation | policy/route authority commit 后 | occurrence frame / default / `0` | static origin + occurrence + activation/route；`ActionIndex=-1` |
| dispatched action | 对应 same-frame/deferred/reliable `Commit` 返回后 | occurrence frame / default / `0` | origin + occurrence + activation/action/target/payload |
| runtime diagnostic | 每次真实 `RecordDiagnostic`，即使 legacy diagnostic snapshot 已满 | diagnostic frame / default / `0` | valid instance 可解析时补 static origin；reason/detail；`ActionIndex=-1` |
| command result | 每条 lifecycle command一次、每个 raw batch一次 | raw command frame / default / raw command sequence | 可解析 static origin + raw numeric command header + batch/provenance/result；不复制 TraceId；`ActionIndex=-1` |
| internal deferred result | 每次真实 deferred result/retention | default / frozen `OriginalDueFrame` / frozen record sequence | frozen origin/target/action/payload；G1 record 没有 original activation frame，不反推 |
| reliable transfer result | 每次 transfer 实际返回后；异常不伪造 | frozen activation frame / frozen due / frozen record sequence | frozen origin/occurrence/target/action + transfer status/detail；未接受为 `Retained` |
| future action result | public typed seam 校验通过后 | publish frame / default / `0` | activation/action/target + result；不能构造任意 internal event |

所有不适用于当前 kind 的 typed ID/entity/target/数值字段保持 default；所有非 action kind 的 `ActionIndex` 必须是 `-1`。source sequence 从 `1` 开始，只在 source 接受记录时消耗；`long.MaxValue` 本身可以接受一次，随后保持 terminal sentinel。拒绝优先级是 ActionResult payload/producer ownership、sequence exhausted、source capacity；capacity reject 不消耗 sequence。source accepted records按 `(Frame, SourceSequence)` 排序，Router 在 frame G 只复制 due prefix。若 Router 已在 G 运行而后续 producer 又写入 `Frame=G`，该记录保留到下一次 Router Tick，并以 overdue 记录交付。

一个 source 必须先绑定且只能绑定一个 `GameplayTriggerRuntime` producer，随后才能绑定一个 Router drain owner；不能先 Router 后 Runtime。observer buffer 也只能属于一个 Router。Router 构造先复制、校验、ordinal sort 整个 registry，再执行 no-fail binding，因此任何 null/空/重复/已绑定失败都不污染后续合法组合。observer disabled 时保留已有 pending、丢弃新 fanout；`Clear` 不清 dropped/high-water/enabled；Router disabled/skipped 不消费 source，也不增加 observer drop。

source/observer pending、source sequence、drop/high-water、Router/observer enabled 和 frozen registry 都是 presentation-only。它们不进入 catalog hash、authority hash、SaveState、replay 或 checkpoint pending 分类；authority restore 不隐式清 presentation。只有 bootstrap/rebuild 的 exclusive boundary 显式调用 `ResetPresentationState()`，且该操作保留既有 ownership/binding 与 enabled 配置。

## Replay Playback / Bootstrap 契约

`GameplayTriggerReplayFrameDriver` 只接受 `GameplayTriggerReplayHeaderContract` 创建的 schema-1 header。framework、resource 和 schema 必须与 options 精确一致；config 必须是 schema-v2 combined catalog hash 的 16 位小写十六进制 identity；`StartFrame=long.MaxValue` 永远非法。header/checkpoint root 预检在 session factory 之前完成，失败不运行 lifecycle。

`Fresh` 创建全新组合并把 command buffer 定位到 header start。`CheckpointSuffix` 要求 checkpoint root 的 schema/config/framework/resource 精确一致、`Frame=F` 位于 `0..long.MaxValue-2`，且 header start 必须严格为 `F+1`。组合根先 `Initialize -> Start`，再通过 coordinator 原子恢复 checkpoint；恢复失败暴露 `CheckpointRestoreFailed + RuntimeSaveStateError` 并销毁 session。两种 bootstrap 都在 Ready 前清空 Router/source/observer 的 presentation transport state，但保留 ownership、registration 和 enabled 配置；bootstrap 期间任何 Tick、pending command 或 command-buffer frame mutation 都 fail-closed。

factory 交付的 composition 必须精确匹配既有默认 ownership 与调度：FailFast Host、唯一注册的 `GameplayRuntimeModule`、同一 Trigger runtime 的 Deferred/Command/Evaluation/Router、可选且必须同 runtime 的 reliable outbox、sealed exogenous source registry、正确 system/module ID/phase/priority、足够的 command/typed reconstruction scratch，以及 start-frame 空 command buffer。相同 ID 的替身、错误 runtime identity、缺失 outbox 或不同调度 tuple 都在 lifecycle 前拒绝并释放已转移 ownership。

每个 frame 必须与 `NextExpectedFrame` 严格连续；`long.MaxValue-1` 是最后可 Tick record，之后进入 terminal，`long.MaxValue` record 不执行。frame admission 在任何 submit/Tick/hash 前完整验证：command count 不超过固定上限；总顺序严格符合 Runtime drain key且 sequence 不重复；source 必须是 sealed registry 中允许对应 typed command 的 Exogenous source；envelope 必须存在且 provenance 为 Exogenous；只允许 Signal/occupancy/scalar 三类 observation；每个 raw batch 的 metadata、ItemIndex completeness/uniqueness、ordered Signal sequence、source reducer kind、每 batch typed maximum、Runtime input batch/item capacity和同 frame 每 source 唯一提交都必须成立。任一 admission 失败恢复整个 command-buffer snapshot，session fault/dispose，不能产生部分 submit、Tick、hash 或 event-source mutation。

成功 admission 后恰好执行一次 `RuntimeHost.Tick(frame)`，再只用 `GameplayTriggerRuntimeHashContributor` 计算 result hash。generic runner 负责把返回 hash 与 snapshot expected hash 比较，并保留 failure frame、expected/actual hash、完整 command context 或原始 typed driver exception。replay snapshot 只保存可信 exogenous observation records；ordered Signal 按 envelope ItemIndex/Signal.Sequence 重建，unordered Signal canonicalize；空帧同样必须播放以推进 continuity。CommandResult、occurrence、activation、ActionResult/ActionDispatched、G1 internal deferred、G2 reliable outbox/transfer 和 TrustedDerived target command 均从 authority/checkpoint 再生成，不得在 snapshot 重复注入。observer 容量、enabled 或 overflow 只改变 presentation diagnostics，不改变 replay authority hash。

## 确定性与事务规则

- lifecycle commands 按 `RuntimeCommandBuffer` 的 `(Frame, SourceId, CommandId, TargetId, Sequence)` 全局 total key 升序应用；不同 source 的冲突由较大 `SourceId` 后覆盖，同键冲突由较晚接受的 `Sequence` 后覆盖。
- fixed batch raw identity 为 `(CommandId, Frame, SourceId, SourceBindingId, BatchId)`；record 接受顺序不替代 `ItemIndex`。缺项、重复 item、metadata/schema/type/provenance 不一致或 reconstruction capacity overflow 时，同 raw batch 全部 records 标记 handled 并整批拒绝，不向 Trigger authority 提交部分输入。Signal、occupancy 和 scalar 的 empty batch 都使用唯一 `ItemIndex=-1 / ItemCount=0` record。
- Occupancy 在 reducer 内按 `GameplayEntityId` 规范排序并去重，输入排列不影响 Entered/Stayed/Exited。
- 整帧 source reduction 完成后，occurrence 按 InstanceId、Subject、Instigator、Kind、Signal/Scalar/Payload/ordering 的完整 key 全局排序；非 ordered Signal occurrence 重建 canonical ordinal，历史 relation 插入顺序不进入输出。
- Scalar batch 同 Subject 重复 sample 整批拒绝；threshold 使用 `Fix64`、显式方向、迟滞和 initial sample policy。
- Unordered Signal 保留重复 multiplicity 并按完整 payload 规范排序；Ordered Signal 必须提供严格递增 sequence。
- source truth 成功归约后不因 condition、policy、arbitration 或 action reservation 失败回滚，也不在下一帧伪造重复 Entered。
- exclusive winner priority 与 accepted execution order 分离；loser 不消耗 count/cooldown。
- exclusive arbitration 的 PerSubject、PerInstigator 和 PerPair scope 缺失所需 entity 时产生 `MissingScopeEntity`，不得绕过分组后被接受。
- action Prepare 失败时按已准备顺序的严格逆序 Abort；只有全部 Prepare 成功才 Commit activation、policy 和 intent。
- internal deferred action 仍参加同一 reservation transaction：Prepare 只占 Trigger-owned slot，Abort 释放且不消耗 sequence，Commit 才以 `OriginalDueFrame = activation frame + 1` 写入 canonical `(due, sequence)` queue。allocator 的 `long.MaxValue` 是可保存/恢复/hash 的 exhausted sentinel；后续 Prepare 返回 `DeferredSequenceExhausted`。
- reliable deferred action 使用相同 transaction，但 legacy sink 的 `TryPrepare/Abort/Commit` 永不调用：Runtime 自己 reserve/abort/commit outbox slot，只有 Commit 才分配 stable sequence 并写完整冻结 record。可靠 reservation 与 internal reservation 都以既有 checkpoint detail 5 阻止重入 capture。
- due reliable record 从 `OriginalDueFrame` 起每 Tick eligible；缺 transfer、目标模块缺失/disabled、target capacity 或 transient reject 都保留原 record。只有 status `Accepted=1` 立即稳定移除；后续同 Tick 的 target 模块异常会使 Host attempt 失败，checkpoint barrier 拒绝该 session，恢复方必须用上一 checkpoint 加 exogenous replay 重建。
- due `SetEnabled` / `Reset` 在 PreCommand 直接作用于冻结的 generation-safe target instance；due `Signal` 只 stage/tag。Command phase 以 external Signal command 的 total-order 位置裁决同 source 的 ordered winner/lifecycle conflict；unordered Signal 在 external batch 留出的 input item 容量内追加 stable deferred prefix。malformed external batch 被原子拒绝，不阻止合法 deferred prefix 推进。
- catalog hash 的 source/definition/route/binding/target/sink 集合使用 catalog 冻结后的 typed-ID canonical order；condition instruction 与 action declaration order 是语义顺序，交换后必须改变 definition hash。
- `TryCreate` 会把每个 action sink 的 `ActionKindId + DeliveryContract` 捕获为 immutable registry entry，再按 captured kind 排序、校验、查找和计算 hash；后续 live getter mutation 不改变 frozen contract，也不会注册新的 kind。sink 对象引用只用于 `TryPrepare/Abort/Commit` dispatch。
- `GameplayTriggerRuntimeHashContributor` schema 3 写入三个 current catalog hash、十二项 runtime options、activation/deferred/reliable allocator、evaluated marker、instance identity/state、canonical relation/route policy state、完整 deferred records 和完整 reliable records。relation 按 `(InstanceId, Subject)`、route state 按 `(InstanceId, RouteId, Subject, Instigator)`、outbox 按 `(OriginalDueFrame, Sequence)` 保持 canonical。
- SaveState payload schema 3 保存相同 authority projection。schema 1/2 只有在旧字段形状精确匹配时才严格迁移，并注入 empty reliable outbox 与 sequence 1。transfer enablement、target module live state、attempt frame/status/detail、`LastReliableOutboxExecutionResult` 和 in-flight marker 不进入 hash/save。
- payload parser 只接受一个 root object；duplicate/unknown/missing/null required property、comment、trailing token/second root、numeric overflow 都以 `InvalidDocument + PayloadJsonInvalid` 拒绝。恢复在所有 schema/config/capacity/key/invariant/entity 检查完成后才构建替换 plan，commit 不做外部调用、校验或分配；成功 commit 同时清空 occurrence/activation/intent/diagnostic/pending input、reservation/staging tag、`LastDeferredExecutionResult` 与 `LastReliableOutboxExecutionResult`，这些瞬态结果不进入 payload/hash。
- root frame 范围为 `0..long.MaxValue-1`，next activation id 为 `1..long.MaxValue-1`；deferred due frame 的数值域允许 `0..long.MaxValue`，且已评估 payload 中每条 record 还必须满足 `OriginalDueFrame <= min(long.MaxValue, LastEvaluatedFrame + 1)`，越界以 `DeferredRecordInvalid=253` 原子拒绝。`due=0` 继续合法，`LastEvaluatedFrame=long.MaxValue-1 / due=long.MaxValue` 也是合法终点；next deferred sequence 允许 `1..long.MaxValue`。合法 Stay schedule 允许饱和的 `NextStayFrame=long.MaxValue`。OncePerPresence 只能恢复到可证明的当前 instance/subject presence epoch，不能伪造 PerInstigator/PerPair presence。
- occurrence/activation/intent/diagnostic/current pending input 等 Evaluate 瞬态 buffer、sink 对象身份、trace/presentation/Unity identity 不进入 authority hash。只允许在一次完整 `Evaluate(frame)` 或承载它的完整 `Tick` 成功结束后读取；authority checkpoint 组合根使用 Runtime barrier，并把 Gameplay world/restored entities 以 order 100、Trigger participant 以 order 200 注册。两个 order 常量只是建议值，复杂组合根须自行分配无冲突 order。
