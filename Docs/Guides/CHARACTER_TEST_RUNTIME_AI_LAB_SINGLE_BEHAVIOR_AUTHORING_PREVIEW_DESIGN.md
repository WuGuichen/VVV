# CharacterTest Runtime AI Lab 行为组装配、运行与编辑设计

> Status: Current
> Scope: CharacterTest internal Runtime AI Lab
> Supersedes: 旧的“单行为草稿 + 测试组合 + 独立预览设置”定义

## 1. 产品主线

Runtime AI Lab 只保留一条用户可理解的主线：

```text
实验设置
→ 为每个角色装配一个正式项目行为组
→ 开始测试
→ 选中运行中的角色
→ 查看运行轨迹 / 行为计划
→ 编辑该角色所装配的完整行为组及其中具体行为
→ 保存项目 JSON
→ 重新开始测试以使用新版本
```

固定原则：

- 一个角色同时只装配一个行为组，不存在“同时装配多个行为组”。
- 行为组由一组有序行为组成；免费寻敌和兜底仍由核心策略约束。
- 实验设置负责阵容、站位、规则以及每个角色的唯一行为组装配。
- 运行界面负责观察、选择角色以及编辑该角色的行为组。
- 行为组组合编辑和单个行为效果编辑必须位于同一个编辑逻辑界面。
- 不再建立“测试组合”“临时行为组”或用户可见的持久草稿概念。
- 项目行为卡和项目行为组 JSON 是正式数据权威。

## 2. 实验设置

实验设置是唯一的对战阵容编排入口，复用现有双方槽位和 3D 站位能力。

每个槽位包含：

- 启用状态；
- 角色；
- 唯一行为组；
- 出生位置；
- 镜像、网格吸附和出生点校验等既有能力。

行为组选择列表必须直接来自项目 `behavior_group_catalog.json`，当前选择必须存在于同一列表中。

实验设置同时提供最小项目行为组资产管理：

- `+`：以当前行为组为模板创建一个新的稳定行为组，写入项目 JSON，并装配给当前角色；
- `删除`：二次确认后删除当前行为组的项目资产；所有引用它的槽位切换到仍存在的行为组；
- 行为组选择弹窗右栏可以编辑名称、描述和标签；显式保存只追加元数据 revision，不发布其它行为配置改动；
- 弹窗内部的选择、筛选、输入和资产操作保持弹窗打开，点击外部空白、`Esc`、再次点击入口、切换选择器或离开实验设置时关闭；未保存输入随关闭或切换行为组丢弃；
- 项目中至少保留一个行为组；
- Player 构建保持只读，不显示可执行的新增和删除能力。

实验设置不提供行为内容编辑；行为组基本信息属于最小资产管理能力。主操作始终是`开始测试`。

## 3. 开始测试与返回设置

点击`开始测试`时校验双方阵容、每个角色的唯一行为组、固定卡版本、站位和帧上限，然后生成不可变运行快照并从第 0 帧开始。

运行过程中：

- 不重新读取项目 JSON；
- 不跟随目录中的最新版；
- 后续保存行为卡或行为组不会改变当前运行；
- 返回实验设置保留当前阵容和装配配置；
- 再次开始测试才冻结并运行新的项目版本。

运行界面的返回按钮必须回到同一个实验设置界面，从而形成：

```text
实验设置 ⇄ 开始测试
```

## 4. 运行界面

运行界面复用现有 3D 战斗场景和 RuntimeFrame 运行轨迹。

基础结构：

```text
┌ 角色选择 ─ 会话状态 ─ 播放/暂停 ─ 单帧 ─ 重开 ─ 返回设置 ┐
├───────────────────────────┬──────────────────────┤
│                           │ 当前角色 / 当前行为证据 │
│       3D 对战运行场景       │                      │
├───────────────────────────┴──────────────────────┤
│ 编辑逻辑 | 行为计划 | 运行轨迹                         │
└──────────────────────────────────────────────────┘
```

角色选择是编辑目标的唯一权威。切换角色时必须同步到该角色在实验设置中的队伍和槽位，并由该槽位解析唯一装配行为组。

## 5. 运行轨迹与行为计划

`运行轨迹`继续作为最主要的预览时间轴，复用现有 RuntimeFrame 缓冲、五轨投影、播放/暂停、单帧、拖动定位、历史场景恢复和返回最新帧能力。

`行为计划`解释当前角色行为组在选中 RuntimeFrame 上的仲裁和衔接结果，不承担正式数据编辑。

历史帧保持只读。用户可以查看旧轨迹，但不能让旧帧编辑反向修改项目数据。

## 6. 编辑逻辑

点击`编辑逻辑`后，编辑对象是当前选中角色唯一装配的完整行为组。

界面必须同时提供两层编辑：

1. 行为组组合层：显示完整有序行为列表，支持选择、复制、上移、下移、启用/禁用和删除非核心行为；
2. 具体行为层：选中列表中的行为后，复用现有行为卡逻辑、条件、阶段、转换和参数编辑器。

二者不是两个互不相干的页面。左侧组合决定该角色会仲裁哪些行为，右侧编辑决定当前行为具体如何发生。

### 6.1 行为配方 Track / Event 时间轴

具体行为层使用统一的行为配方时间轴。完整信息架构、时间语义、Event 类型、交互矩阵、Composer 合同、当前交付状态和验收清单以 [行为配方大时间轴设计](CHARACTER_TEST_RUNTIME_AI_LAB_BEHAVIOR_RECIPE_TIMELINE_DESIGN.md) 为专项权威。

本产品层只保留以下不可违反的结论：

```text
行为配方 → 多条同级 Timeline → 自动 Track → Event
```

- `behavior-card-logic.v5` 的 Timeline/Event 是保存、编译、运行、快照和调试的统一权威，不再只是旧关系图的编辑投影；
- 每条 Timeline 从自己的局部 `0f` 开始，共享帧比例和横向滚动，但同一行为配方同时只有一条 Timeline 执行；
- Track 仅由 Event 类型自动生成，不持久化、不参与运行；所有可编辑行为内容都必须表现为 Track 上的 Event；
- CharacterAction 的完整动作时间轴作为 Event 被引用，不在行为层展开为嵌套子时间轴；行为配方不再直接创作 Ability Event，需要技能动作时引用 Ability 绑定的正式 CharacterAction；
- TriggerEvent 只使用具体 Predicate、LocalFrame 或绑定动作实例的 PrimaryActionSignal；结果只允许进入另一条 Timeline 或返回行为决策；
- Timeline 之间通过 Event 内的目标标签和定位表达，不使用端点、箭头或关系连线；
- 右下区域继续保持 `1300×412` 与双轴滚动，增加内容只增加固定高度的行，不改变已有 Event 形状；
- 选择 Event 后，完整属性统一进入右上 Inspector；时间轴本体只承担选择、定位和适合直接操作的时间/顺序手势；
- 新增 Timeline 及其自动后继 Event 必须是一个原子 Undo 事务；不能为 MoveToTarget 或纯 Logic 编造抽象的完成条件。

编辑逻辑界面使用三栏宿主：左侧整卡概览及当前组列表，中央上方复用实际预览相机、下方为事件时间轴，右侧为所选对象属性。编辑逻辑、行为计划、运行轨迹入口仍保持可达。预览可临时占满工作区，返回保留分隔比例、选择、滚动和镜头；布局操作不重启测试。具体实施与尚未完成的战术作者源接线见[任务04布局基线](../../StorySource/玩法基石/任务/任务04_T4-3_布局与预览接入基线.md)。

用户不需要理解 draft、hash、stable ID 或项目路径。这些技术证据只在冲突或错误详情中按需显示。

## 7. 保存语义

编辑期间允许内部使用短生命周期、内存中的可撤销事务，但产品语义中不存在“进入草稿”或“草稿属于行为组”的状态。

`保存行为组`执行：

1. 校验完整行为组和所有固定行为卡版本；
2. 检查项目目录乐观并发 hash；
3. 向 `behavior_group_catalog.json` 追加新的组 revision；
4. 通过 Editor-only 写入桥使用本机 `UserSettings/RuntimeAiLab/ProjectCatalogRecovery` 下的临时文件与单份 `.previous`，完成重新解析、原子替换和失败回滚；这些恢复文件不进入 `Assets` 或 Git；
5. 保存成功后提示当前测试仍使用启动时冻结版本；
6. 用户显式重新开始测试后，新运行才使用新 revision。

如果编辑了具体行为卡，则先发布卡片新 revision，再显式更新当前行为组引用并保存组 revision。行为组不得浮动引用“最新卡片”。

## 8. 数据边界

- 正式行为卡：`behavior_card_catalog.json`；
- 正式行为组：`behavior_group_catalog.json`；
- 每个角色槽位：一个具体行为组版本；
- 每个行为组：有序且固定 revision/hash 的行为卡引用；
- 每次测试：不可变的角色、组、卡和编译 Profile 快照；
- C# seed：只用于测试夹具和 Editor 显式恢复项目目录，不参与正常加载；
- Player：只读项目目录，不能创建、删除或保存项目行为资产。

## 9. 复用约束

必须继续复用：

- `CharacterTestArenaMatchConfig` 双方槽位和单行为组装配；
- 项目行为卡/行为组 catalog、validator、compiler 和 Editor 写入事务；
- Runtime AI Planner Profile 编译与不可变运行快照；
- 现有角色选择、场景点击选择和 Setup 站位能力；
- 现有 Behavior Card 逻辑编辑器；
- 现有 RuntimeFrame 缓冲、Seek 和五轨运行轨迹；
- 现有 FairyGUI Composer-owned Runtime AI Lab 包。

禁止新增第二套行为执行器、JSON Tick 解释器、帧缓存、时间轴 authority、隐藏正式行为组或玩家卡组权威。

## 10. 验收场景

- 实验设置中每个角色只能选择一个行为组；
- 设置页可基于当前组新增项目行为组，新组立即装配到当前角色并出现在选择列表；
- 删除需要二次确认，不能删除最后一个组，引用被删组的槽位会切换到有效组；
- 开始测试后切换角色，编辑目标同步切换到该角色唯一装配行为组；
- 编辑逻辑同时显示完整行为列表和当前具体行为编辑器；
- 每个 v5 Timeline 恰好显示为一条同级时间轴，全部时间轴使用同一阶段帧比例且支持双轴滚动；
- EntryEvent、PrimaryActionEvent 和 TriggerEvent 都显示为自动 Track 上的 Event，不出现轨道外卡片、连接端点或关系线；
- 实际帧可直接辨认当前执行 Timeline、所属 Track、具体触发条件与目标结果；当前播放头只在当前 Timeline 内显示局部帧；
- 新增 Timeline、三类 TriggerEvent、两类结果、右上 Inspector、撤销/重做和目标 Timeline 定位都直接读写 v5 权威语义；
- 组合层操作只修改当前行为组的待保存事务；
- 保存行为组会写项目 JSON 新 revision，不改变当前运行；
- 重新开始测试后才使用保存的新 revision；
- 运行轨迹可以拖动到历史 RuntimeFrame，历史帧保持只读；
- 返回实验设置后阵容、站位和唯一行为组装配保持不变；
- Player 构建能运行项目目录，但项目资产管理和保存为只读。

最终收口判断：**实验设置决定每个角色唯一装配哪个行为组；运行时选择角色；编辑逻辑同时编辑该角色的行为组合与具体行为；保存写入项目 JSON；重新开始测试后生效。**
