# LCC 单任务执行文档模板

> Status: Guide
>
> 适用路线：[CharacterTest 大型角色接触、部位状态与权威姿态实施总台账](CHARACTER_TEST_LARGE_CHARACTER_CONTACT_DEVELOPMENT.md)
>
> 本模板定义 LCC 工作包从拆分、派发、实现、审查到状态晋升的最小合同。复制模板不代表任务已经具备派发条件；LCC 使用 `Audit-Frozen` 与 `Production-Frozen` 两级准备度，避免要求 T0 在尚未审计源码前伪造精确文件和测试入口。

## 1. 文档头与状态权威

每份任务文档必须明确：

- 唯一任务 ID、父里程碑和任务类型（只读审计、生产实现、资产、验收或独立审查）；
- 工作包状态只由父里程碑工作包表维护，子代理不得修改父里程碑或总台账状态；
- 任务文档内的“实际执行记录”只保存事实与证据，不自行宣布父状态；
- 明确前置任务和允许并行的兄弟任务；前置未 `Verified` 时不得开始生产写入。

## 2. 必填执行章节

每份任务文档必须包含以下可执行内容：

1. **任务结果**：一句可观察的完成结果，并明确不等于什么。
2. **非目标**：列出本任务不得提前实现的后续能力。
3. **前置与并行**：冻结 DAG、可并行关系、共享热点和合并顺序。
4. **必读输入**：只列当前任务需要的合同、接口、源码和测试入口。
5. **写入所有权**：精确到目录/文件职责；列出只读和禁止写入范围；共享文件必须指定唯一 owner。
6. **冻结合同与失败行为**：字段、身份、排序、容量、schema、兼容、typed failure 和 fail-closed 边界。
7. **实施清单**：按生产链路拆成可逐项核对的步骤。
8. **验证与证据**：测试入口、fixture、断言、Unity/Playable/性能要求和证据保存位置。
9. **派发合同**：子代理任务文本、完成回报格式、停止条件和不得代替主代理做出的状态判断。
10. **实际执行记录**：初始为“未执行”；由执行者记录精确文件、测试结果、证据、限制和剩余风险。

## 3. 写入所有权与并行门禁

- `Audit-Frozen` 前，每份文档必须冻结职责/目录级 owner、禁止范围和共享热点候选；达到该状态后只允许派发里程碑 T0 只读审计。
- T0 只在自身冻结表记录当前源码对应的精确文件/partial、测试 filter、证据目录和交接点，并提交结构化回报；主代理复核后回写各生产任务，再把当前父里程碑提升为 `Production-Frozen`，T1+ 才可生产写入。
- 同一生产文件在同一批次只有一个写入者；跨任务共享文件由 T0 文件级交接表指定当前 owner 与后续允许修改范围。
- 子代理开始前先检查工作区，保留用户和其它代理的既有修改；发现同一文件已有非本任务改动时停止写入并报告。
- 只读审计代理不得顺手实现；实现代理不得修改总台账、父里程碑状态、兄弟任务文档或能力等级。
- Unity 正式资产只能由 Unity Editor、Unity MCP 或仓库正式生成器写入；不得手工伪造 `.meta` 或序列化资产。
- 独立审查与实现使用不同代理上下文；审查者默认只读，除非主代理另行派发修复任务。

## 4. 状态与证据晋升

执行包准备度：

```text
Drafting -> Audit-Frozen -> Production-Frozen
```

- `Audit-Frozen`：当前总台账登记的全部任务边界、DAG、职责 owner、禁止范围、验证类别和回报格式经检查；只允许派发当前里程碑 T0。
- `Production-Frozen`：当前里程碑 T0 已 `Verified`，精确文件/partial owner、test filter、证据落点和合同表已由主代理从T0回报写入各生产任务并复核；允许按 DAG 派发 T1+。
- 准备度不证明实现存在，也不改变工作包的 `Planned/In Progress/...` 状态。

```text
Planned -> In Progress -> Implementation Complete -> Verified
```

- 派发生产任务前，主代理先在父里程碑更新该任务为 `In Progress`。
- 子代理回报“完成”最多证明候选实现形成；主代理检查 diff、边界与证据后才可记 `Implementation Complete`。
- focused tests、Unity refresh/compile、对应 Playable 或直接画面、NoAlloc/网络门禁、独立审查按任务要求全部满足后，主代理才能记 `Verified`。
- 设计文档、源码存在、测试代码存在、异步测试已启动或 Debug Gizmo 截图都不能单独证明 Runtime 已验证。
- `Blocked` 仅用于确认的外部阻断，并记录解除条件；普通失败保持当前状态并继续修复。

## 5. 子代理派发文本最小格式

```text
执行 <TASK-ID>，严格以 <TASK-DOC> 为唯一任务边界。
先读取父里程碑指定章节、路径 AGENTS.md 和任务必读输入。
只写“写入所有权”列出的范围；保留工作区其它修改，不修改父状态文档。
完成后报告：
1. 实际修改文件；
2. 合同/兼容/失败行为；
3. 执行的测试与原始结果；
4. 未执行验证及原因；
5. 风险、冲突和建议的主代理复核点。
遇到停止条件立即停下，不自行扩展范围。
```

## 6. 主代理集成检查

- 核对实际 diff 只覆盖任务范围，且未覆盖工作区既有修改；
- 核对公共 API、程序集边界、schema 版本和正式资产写入方式；
- 按风险重新执行关键 focused tests，不直接采信子代理摘要；
- 高风险网络、拓扑、碰撞或资产任务交给独立只读审查；
- 独立审查必须给出完整 P0～P3 清单；P0/P1 必须清零，保留的 P2/P3 必须逐项记录接受理由、owner、后续任务/截止门禁，不能静默忽略；
- 在父任务表和历史中记录真实证据、未验证项与限制；
- 只有当前任务 `Verified` 后才解除依赖它的后续任务。

## 7. 集成与回滚要求

- 每个任务在派发前记录可回滚边界：本任务作者源、生成输出、源码、schema 和正式资产分别由谁恢复或前向修复。
- 回滚只触碰当前任务 owner 范围，不使用 `git reset --hard`、全量 checkout、清理工作树或覆盖其它人的修改。
- Authoring/正式资产以保留作者源并重新生成作为恢复路径；future/unknown 原文和 `.meta` 不得丢失。
- 已进入正式 schema 的状态默认通过兼容迁移或前向修复收口，不擅自降版本；尚未验收的候选 schema 可在主代理确认无外部消费者后撤回。
- 子代理发现必须跨 owner 修复时停止并回报，由主代理决定回派、串行合并或调整任务文档。
- 版本化证据摘要写入当前任务实际记录；Game View/浏览器等直接证据使用 `Docs/Evidence/LCC/<TASK-ID>/`，测试 job id、filter、通过数和原始结果位置逐项登记。T0 在 `Production-Frozen` 前冻结每个任务的精确 filter 与证据文件名。

| 状态权威 | 父里程碑工作包表 |
| 执行者 / 审查者 | 未派发 |
| 实际分支 / 提交 | 未执行 |
| 实际修改文件 | 无 |
| 自动化结果 | 未执行 |
| Unity / Playable | 未执行 |
| 性能 / 网络 | 未执行 |
| 独立审查 | 未执行 |
| 限制 / 风险 | 未执行，不能声明实现存在 |
