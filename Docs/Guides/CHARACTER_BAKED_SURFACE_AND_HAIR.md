# 角色合图烘焙与头发

制作源继续使用 Color Palette、Surface Profile 和任意基础色合成层。运行时主 Shader `WGame/CharacterStylizedLit` 只读取一张底色图、一张材质控制图及网格发流数据，不再提供色板、独立 FaceDetail 或纯色模式。当前烘焙接入对象包括 `000009 / C001_1` 和已从色板转换发布的 `000008`。

## 烘焙 FBX 切线精简

烘焙导出在生成文件后、计算模型哈希之前，移除 HairFlow/HairMeta 通道附带的 FBX 切线和副切线层及其引用。保留 UV0 的切线坐标系、三个数据通道、法线、顶点颜色、蒙皮和骨架；原有压缩属性数据不重新编码。历史色板导出保持原样。只接受明确的 UV0/HairFlow/HairMeta 合同，重复处理不改变文件，无法识别的布局拒绝处理。

`000009` 已在不重新烘焙贴图、不修改 Work 的情况下同步精简正式产物：8,091,308 → 5,705,036 字节（7.72 → 5.44 MiB，约减 29.5%）。模型描述和资源目录哈希同步更新，FBX 的 Unity GUID 不变。Unity 导入后的网格数据逐项一致，因此这是文件体积优化，不代表同等幅度的运行内存或帧率收益。导入后的该模型实际为 109,918 顶点，高于源网格的 23,282 顶点；不能用源顶点数估算最终网格内存。

新导出自动应用该规则；预览输入指纹包含精简器代码，旧候选需要按原流程重新验证/烘焙后发布。详见 [切线精简验收](../Validation/WGameShaderFamily/CharacterFbxTangentPruning.md)。

## Shader 分工与历史兼容

- `WGame/CharacterStylizedLit`：烘焙主路径，保留原 Shader GUID、光照属性名、头发效果与运行时效果。材质面板按烘焙贴图、头发、风格光照和运行时效果分组；生成材质的贴图、头发参数与渲染面由烘焙描述拥有，面板只读。
- `WGame/CharacterPaletteLegacy`：历史色板、独立 FaceDetail 和纯色兼容；旧角色导入、共享色板生成器、预览标记与纯色 Demo 使用此 Shader。
- `WGame/CharacterStylizedLitLite`：历史色板对照方案，未改为烘焙版本。传统材质仍使用 `WGame/CharacterTraditionalLit`。

Unity 菜单 **MxFramework → Rendering → Migrate Character Shaders** 显式迁移旧混合 Shader 材质。迁移保留材质 GUID、纹理、光照和效果值；色板／纯色转到 Legacy，烘焙材质保留主 Shader 并清理旧模式标记。重复执行不重复改写。矛盾的模式标记、不完整的烘焙贴图或无法判定的材质跳过并记录到 `Temp/CharacterShaderMigration/latest.txt`。打开工程不会自动迁移，也不会批量重烘焙。

CharacterStudio 的 **角色材质** 入口直接显示烘焙资源、制作来源和校验问题，不依赖全局色板目录；历史角色显示“历史色板兼容”，无历史绑定的新角色显示 Blender 烘焙发布引导。包格式、模板 ID、纹理通道与 UV 合同保持不变。

新角色登记只保存制作配色 Profile，不再根据 PaletteToken 自动创建启用的历史色板运行时绑定；已有包的绑定保持原样。

### CharacterStudio 三维预览

本体预览优先读取 `character_baked_surface_binding.json`，加载其中指定的 FBX、BaseColor 与 SurfaceData。使用原始 UV0 采样两张贴图；UV1 只表示有正负值的发流方向，UV2 只表示根梢位置和头发标记，不能套用旧色板的 UV1 → UV0 转换。烘焙本体不生成色板 usage；武器继续独立使用原有预览路径。

底色按 sRGB、控制图按线性数据读取；Profile 单独使用最近点采样，防止过滤产生不存在的表面类型。网页使用 Three.js 表面光照与各向异性头发近似，不承诺和 Unity 风格光照逐像素一致。描述、贴图或网格数据不完整时显示明确的预览错误，不静默改用色板或 FBX 内嵌材质。

000009 的正式制作源为 `ArtSource/Characters/000009/Blender_Work/000009_work.blend`，以 `authoring_manifest.json` 的 `authority.blenderPath` 为准。源文件不在这个位置时，面板与后台发布器拒绝替换该角色的正式产物。烘焙回执同时记录 `authoringSourcePath`、已保存源文件的 `authoringSourceHash` 和包含当前内存图像的 `sourceBlendHash`。

## Blender 操作

在 WGame 角色画板安装／热更后，打开三维视图侧栏 **WGame → 头发与烘焙设置**。绑定助手中选择当前角色编号；正式 Work 路径中的编号可自动识别。

1. 上色时选择“02 哑光头发”或“03 柔光头发”，对应面自动作为头发；改成其他材质类型后自动退出头发范围。“选中头发区域”用于检查识别结果，不修改材质。材质交界按面区分，共享顶点不会把相邻皮肤面带入头发区域。
2. “生成发流并显示箭头”。默认以头部骨骼和连通发束估计根部；需要修正时，选择根部顶点标记，或添加从根到梢的引导线。添加引导线优先使用编辑模式中的头发选区，其次使用靠近头发的 3D 光标，否则自动放到头部附近；创建后自动进入曲线编辑并聚焦，开启可见叠加层。选中已有引导线继续添加时，沿用其目标网格。第一点为发根，沿发束调整后选回角色网格重新生成发流。
3. 通常直接使用默认头发光照参数，无需逐角色调节；宽度、强度、偏移和遮蔽等参数收在默认折叠的“高级设置”中，特殊需求时再展开。已有角色设置保留。制作模式中的头发预览是 Blender BSDF 的近似；再按一次恢复源材质。导出会自动使用源材质，不烘焙预览高光。
4. 选择输出尺寸：**512、1024、2048、4096 或自动**。显式尺寸允许缩小颜色细节；自动模式下纯色板角色从 512 起步；带实际贴图细节的角色仍按细节密度选择，最多 4096。
5. 点击 **烘焙并预览**（WGame → 头发与烘焙设置，或 WGame Rig → 发布角色资产）。它把当前制作网格和未保存的贴图像素写入临时快照，在后台生成 FBX、BaseColor、SurfaceData 并做独立 FBX 回读验收；不会保存覆盖 Work、写入正式导出目录、同步角色包或触发 Unity 导入。
6. 烘焙成功后自动打开 **临时烘焙预览 · 尚未发布**。可以转动预览灯光、对比头发效果；不满意就点 **返回制作** 修改后再次烘焙。后台运行期间可继续编辑；如果制作内容已经变化，不自动切走当前工作，提示重新烘焙。
7. 满意后点击 **确认并发布到 Unity**。系统先核对当前制作输入及候选文件哈希，再保存制作源与未保存贴图，发布已查看的模型／贴图字节，不重新烘焙。网格、材质节点、贴图像素、表面类型、发根／引导、蒙皮或烘焙尺寸／头发参数改变时，要求重新“烘焙并预览”；视角、选区和节点排版不影响结果有效性。缺少候选或尚未查看时不会直接发布。已有历史色板角色未主动烘焙时仍保留原兼容导出路径。

选中或编辑引导线时，视口显示绿色“发根 · 起点”、橙色“发梢 · 终点”和青色方向箭头，位置随控制点实时更新。标记顺序与发流算法读取的控制点顺序一致，不按画面中的上下位置猜测。摆反时用“反转根梢方向”交换首尾，保留曲线形状；只影响当前活动引导线，之后选回角色重新生成发流。标记属于视口叠加层，不生成额外场景对象，也不进入烘焙产物。

“头发与烘焙设置”中的引导线列表支持直接点击切换，当前编辑项高亮；切换会保留控制点修改，自动进入目标引导线的编辑模式并聚焦。列表按所属角色网格筛选，支持直接改名。“返回角色网格”可选回引导线绑定的网格，随后点击“生成发流并显示箭头”，无需到大纲视图来回寻找对象。

“生成发流并显示箭头”也可直接在引导线编辑模式下使用，成功后保留当前选中对象和编辑模式。未选中对象时，优先使用引导线唯一指向的角色，否则寻找唯一使用头发材质的网格；存在多个目标时提示选择，不猜测。面板保留生成结果或错误信息，箭头叠加显示在头发表面之上。修改材质类型后，重新生成发流以刷新方向和箭头；不再包含头发材质时，重新生成会清除旧方向和箭头。临时预览需要重新烘焙才会更新；Unity 资产需确认发布后更新。

引导方向冲突仅针对几乎重合且反向的强约束；不同位置引导线的等距边界按最近引导处理，不因方向相反就误报。真正冲突时，面板会标出相关引导线，并选中冲突顶点；修正后重新生成会清除错误标记。此判断不自动移动、反转或删除作者的引导线。

头发范围以材质类型为唯一依据，旧文件中的手工 `WGameHairRegion` 标记不再覆盖上色结果。根部标记和引导仍作为可选制作数据保留，不占用骨骼权重。预览烘焙只处理临时快照，制作源在确认发布时才保存。保存或清单同步失败时停止发布；烘焙失败不会改动正式产物。候选、快照和日志保存在 `Temp/baked-preview-<id>-*/`，发布暂存和上次成功产物备份在该候选目录的 `publish_<id>/` 下。本次候选属于当前 Blender 会话，重新打开 Blender 后需重新烘焙；目录中的临时结果不会自动被当成已确认版本。

发布用的 Authoring 导入工具在本次 `publish_<id>/` 内独立编译，避免与正在运行的 CharacterStudio 服务争用程序文件；编译成功后才开始替换正式产物。详细编译与导入日志分别为 `authoring-build.log`、`import-unity.log`，失败时 `publish.log` 同时显示具体错误及日志路径。

### 查看和修改手动发根

“头发与烘焙设置”显示手动发根总数及当前选中的发根数量。开启“显示发根标记”后，绿色点表示已经标记的发根，取消顶点选择后仍然可见；标记支持透视，但隐藏顶点不显示，烘焙预览中不显示制作标记。

在网格编辑模式选中发束起点附近的少量顶点后点“标记根部”；不要选整片头发。空选区和非头发选区会提示，物体模式不会误用上次遗留的顶点选择。“清除选中根部”只取消选中顶点的标记；“选中已标记发根”可以检查或清理当前可见的手动标记。修改后清除旧箭头并提示重新生成发流，绿色标记立即更新。未手动标记的发束仍由现有算法尝试自动找根，绿色点不代表自动推测的根。

### 直接查看烘焙前后的 UV

三维视图 **WGame → 头发与烘焙设置**，以及 UV 编辑器 **N → WGame → 制作与烘焙 UV**，都有以下按钮：

- **制作 UV**：切到源模型的 DetailUV 和细节图；没有细节 UV 时显示 PaletteUV。
- **上次发布 UV**：查看正式导出目录中的旧结果，不执行烘焙，也不是当前未发布的候选。
- **查看本次烘焙**：重新打开当前会话的临时候选，查看前检查是否过期。
- **返回制作**：移除临时预览，恢复原场景、工作区、活动对象和编辑模式。保存文件、打开其它文件或热更插件时也会先关闭预览，防止把副本写入 Work。

烘焙预览默认使用 **按制作材质对照**：保留制作视口的工作室环境／场景光设置和色彩管理，按同一 Surface Profile 还原粗糙度、金属度、高光与皮肤散射；骨架叠加显示关闭。底色数据改用烘焙图，默认不叠加额外的风格化头发响应。**查看运行时风格（近似）** 才切到独立灯光与发流双亮带，可以转动预览灯光；再次点击回到制作材质对照。

这是 Blender 实时着色近似，Unity 的最终光照仍以 Unity 为准。预览灯光、材质、切线符号属性均属于临时副本，返回制作时清理，并恢复原视口的灯光设置。保存时也会先返回制作。

默认头发着色使用柔亮发束风格：主高光保留柔和边缘并提高可读性，副高光收窄、减弱；浅色低饱和度头发的阴影增加少量冷灰紫层次，彩色与深色头发不套用这层白发阴影色。Unity 不再将已经压缩的漫反射与高光一起重复压缩；Blender 同步亮带曲线、哑光／柔光比例，并读取预览主光的实际颜色和强度。现有烘焙参数继续有效，无需重烘焙才能采用新版着色响应。

预览场景携带独立的角色编号、显示名和制作源路径，不复制制作场景的绑定设置。WGame Rig 在此模式下只显示“角色编号 · 名称 · 烘焙预览”、制作源和“返回制作”，不会把空设置误报为未登记；Rig 的登记、绑定、权重、保存和发布入口同时通过菜单可用性与执行检查拦截。已启动的 Unity 导入监控可以继续完成。角色画板也隐藏制作配色控件；返回制作后恢复原设置及操作状态。

## 烘焙规则

- 头发允许 UV 重叠；仅在多个头发三角面共享的贴图像素内将 AO 设为 1（无遮挡）。以每像素四个内部采样点判断覆盖，相邻三角面的共边不算重叠；部分重叠不扩大为整面禁用。不重叠区域保留原 AO、AO 强度设置和头发光照，其它控制通道不变。导出在最终布局烘焙后执行该处理，Unity 导入也对旧烘焙包执行同样处理，再生成 mip。无需为了 AO 拆开已有共享 UV。

- 纯色板路径（导出器 1.5.0）：仅当使用中的材质都是直接 `PaletteUV → 最近点 sRGB 色板图 → Principled Base Color`，且每个面落在同一色格时启用。按源色板逐面直接写入 BaseColor，不通过 Cycles 光线采样推测颜色；存在实际细节混合、线性采样或其它颜色节点图时保留通用烘焙。
- 纯色图缓冲区按声明的 sRGB 值写入并保存，不额外重复解码。恒定区域按原 RGB 字节合并，保留颜色／材质类型边界。头发仍保留现有几何 AO 控制数据，因此不将所有头发无条件压成一个共享色格。
- 跨面出现不同纯色不等于手绘细节。已证明逐面恒定的色板区域按实际表面积和控制数据预算分配 UV；只有实际使用的纹理细节才按其原有纹素密度分配。未被颜色图使用的旧 DetailUV 不决定纯色板布局。
- 从连接到 Principled BSDF 的 Base Color 节点提取最终颜色，Emit Bake 不包含灯光、阴影或显示变换；贴图内容不做语义解释。
- 保留有效 DetailUV 岛的内部映射，包括使用重复采样而跨越 0–1 边界的细节。头发按连通区域沿根梢方向开缝，使用 Minimum Stretch 展开；少量退化或翻折面保留原来的安全展开，不因一个小面放弃整片头发。
- 先逐面检查制作输入：色板最近点采样落在同一像素时不受 UV 浮点尾差影响，控制数据按实际输出的 8 位值比较。不同类别、真实渐变、线性采样的 UV 差异不会直接合并。
- 探测烘焙后进一步检查 UV 岛，并逐面提取其中输出恒定的非头发区域；剩余区域保持原有连接关系。只有最终 8 位底色和 RGBA 控制数据均恒定且一致时才共享色格。手绘细节区域受保护，即使探测分辨率暂时看不出变化也不会被当成纯色丢弃；头发仅在整个岛恒定时共享，保留变化的几何 AO 岛以避免重新碎片化。
- 细节复用按原始 DetailUV 三角形的实际重叠判断，包括完全重叠、部分重叠和镜像映射。相同材质节点图、相同非细节输入及相同控制数据的面可共享；同组使用一个坐标变换，保留原来部分重叠的位置关系，不要求网格顶点或三角化相同。冲突按面拆分，其余兼容部分继续复用。仅包围框相交或边界接触不算重叠。
- 复用判定不依赖低分辨率探测图的视觉相似性，避免抹掉细小绘画。头发的兼容细节可共享，重叠像素的几何 AO 按上面的规则中和；位置／法线相关颜色输入、无法证明兼容的节点图保留独立区域；不同材质节点图即使暂时看起来相同，也不会猜测合并。
- 共享纯色格按颜色及材质数据排列在紧凑色条中。细节和 AO 区域使用全图联合轮廓打包，不再预留固定高度的 AO 分区，也不把不规则岛的整个矩形外框算作已占用空间。色条只占实际色格面积，行尾空白仍可使用。
- 候选布局以原始 DetailUV 的相对尺寸为基准，比较不同旋转和排列，并校验表面数据的最低像素预算。临时二维代理只用于打包；源网格保持不变。共享细节组使用同一个坐标变换，防止打包时再拆开。最终布局按目标分辨率独立检查实际覆盖及扩边不相撞。
- 最终布局完成后从原材质节点重新烘焙，避免放大先前的低分辨率像素。已证明恒定的色格连同留边直接填充，防止小三角形漏采样。`atlasLayout` 记录共享块数、细节块数和表面块数；`sourceRecommendedSize` 按最终 UV 密度计算。
- 头发的局部 AO 只进入材质控制图；底色不添加烘焙明暗。
- 发光权重由顶点权重乘以源材质实际的 Emission Strength；材质关闭发光时输出 0，避免把默认全白的顶点通道误当作已启用的发光。RGB 细节图不参与语义判断。
- 暂不支持混合多个 BSDF 后猜测“基础色”。这种输入会明确报错，需把颜色层接到一个 Principled Base Color。

## 运行时合同

`config/character_baked_surface_binding.json` 使用 `mx.characterBakedSurfaceBinding.v1`，记录所属包、模型与两张纹理的包内路径／SHA-256、尺寸、UV 布局、工具版本和头发参数。

| 数据 | 含义 |
| --- | --- |
| BaseColor | sRGB RGB；不透明输出 A=1 |
| SurfaceData | 线性 RGBA：AO、Rim、Emission、16 类 Profile 中心值 `(8+16×profile)/255` |
| UV0 | 完整 BakeUV |
| UV1 | 发流在最终切线基准内的二维单位方向 |
| UV2 | 根部到梢进度、头发标记 |

控制图使用无损存储。分类通道按三角面覆盖生成，不做颜色抗锯齿；Unity 自建 mip 时取实际出现最多的类别，同票取较小编号。Shader 对类别使用离散 mip 和点采样，其余通道正常过滤，避免混合出不存在的材质。

Unity 导入法线和切线，保持 UV 顺序及完整精度。发流通过蒙皮后的切线基重建。新模式与旧色板模式互斥；旧 `CharacterPaletteBinding` 跳过烘焙材质。描述存在但损坏时阻止导入，不回退到旧外观。

头发沿发流计算宽主亮带和弱副亮带，接受光照衰减、阴影和局部 AO；根部暗化与逆光柔光不改变源贴图。风格化头发使用原有角色材质，不增加透明 Pass。

头发双亮带同样使用 Surface Profile 的 `specular` 强度：当前哑光头发为 0.06，柔光头发为 0.18。Unity 与 Blender 烘焙预览一致，不再用固定 0.6／1.0 替代这一材质响应，以避免哑光黑发出现大面积白亮带。头发参数仍控制亮带形状与相对强度，底色贴图不被改写。

### 复杂头发的 UV 展开（导出器 1.4.0）

普通发束仍先沿根梢切缝展开；只有求解退化或翻折的区域，才补充拓扑切缝，把带孔、连接复杂或局部方向冲突的表面展开成可求解的 UV 区域。不会改变源模型的顶点、三角形或法线。不同头发表面类型沿边界分岛，保留控制图分类的留边，减少低分辨率下细三角形误采相邻类型。求解后再次检查退化／翻折，仍失败的面才采用安全回退；不是简单忽略校验。
