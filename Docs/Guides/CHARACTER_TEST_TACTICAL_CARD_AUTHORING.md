## 接近意图的可见提前结束事件（2026-10-09）

所有标准“常规移动面向目标接近”共享源现在显式保存第三条持续事件：“到位且面向达标 → 结束接近段”。它与移动、转向从本段 0 帧开始，结束关联本段模拟结束帧。其条件在时间轴 Inspector 中可见、可编辑：目标作用域下“全部满足”，包含引用本段移动事件配置的“移动到位”及引用本段转向事件配置的“面向达标”。引用链为“装配动作的允许朝向范围 → 转向事件的面向参数 → 结束事件的面向达标条件”，结束事件不另存角度阈值。无关联动作的纯移动源在转向事件中显式配置面向容差；结束条件仍引用它。条件未满足时保持原移动／转向；同时满足后释放本段控制，跳过本段剩余时间，继续后面的出招段。配置时长仍是原有正常结束边界。

“添加事件…”菜单提供“结束当前意图段”（作者操作 `CompleteBlock`）。它只作用于所属的不含角色动作的固定时间意图段，不退出整张卡；没有结束条件、没有所属事件段或所在段包含角色动作时阻止编译。事件条件的“逻辑组 / 动作数据 → 移动到位／面向达标”选择明确的移动／转向来源，保存为 `MovementArrived`／`TurnAligned` 绑定。转向事件中的“面向参数”选择引用装配动作朝向或显式容差，界面显示引用及当前解析范围。删除被引用的移动／转向事件时显示影响，失效引用阻止运行。

升级由 Editor 的 `MxFramework/CharacterTest/Tactical Content/Add Visible Approach Completion Events` 显式执行：认证原发布内容后追加新 revision，按原工作区事务更新共享定义与测试卡，保存可见事件，不在编译器或 Tick 中偷偷生成完成规则。重复执行不重复添加事件；已冻结历史保持原源，不能以新源冒充旧回放。无法认证的旧工作区保留并报告；测试卡恢复草稿保留用户修改，只有备份能证明保存基线仅经过本次升级时才更新 expected revision/hash，既有其它冲突继续保留。

专项验证类别为 `VisibleApproachCompletion`，覆盖距离或角度单独满足时不提前结束、同时满足后继续出招、作者源往返及升级幂等性、修改被引用的转向参数后重新编译改变完成判断。正式 Game 帧显示与真实场景执行证据另行记录，不由这组四项 EditMode 结果代替。

## 统一术语与当前工具名称（2026-10-01）

统一定义以[《角色动作与战术行为卡》第零章“统一术语与数据关系”](../../StorySource/玩法基石/角色动作与战术行为卡.md)为唯一权威：事件 → 意图 → 组合（可选）→ 模板 → 卡 → 卡牌实例 → 卡组。动作、动作槽、装配、预设以及制作／验证／版本／运行状态的边界也在该章维护，本指南不另设一套层级。

制作流程可以只保留动作槽及参数占位；实际卡组使用前，按装配配置填入具体动作和参数、派生可用卡并准备执行数据。槽位未填时可以表达模板流程，但不能显示成已经有真实动作距离或时长的可执行配置。当前工具中的具体动作选择、校验和测试限制仍按下文实现说明处理；本次命名定稿不等于已经修改这些入口。

兼容阅读：当前“基础战术卡库／卡源”中留槽位的流程属于模板制作语境；“角色测试库／共用测试库／已配置测试单卡”承载验证配置，不因此获得正式持有实例身份；“封装”菜单承载已有共享定义，按实际内容理解其意图或组合用途，不再把“封装”当作独立层名。“另存独立封装”、`CharacterTestTacticalAuthoringTemplates` 等现有菜单／类型名暂保留，模板工厂方法也不自动等同于完整的战术模板数据对象。

后文的“封装实例”指流程中的引用节点，不是持有的一份卡牌实例；“行为组”及其 entry 仍是现有配置结构，不能未经身份合同核对就改称已经实现的卡组和卡牌实例。草稿、测试配置、发布 revision 与冻结运行状态继续使用原保存、编译和发布事务，本轮不迁移数据。

## 基础卡与已配置测试单卡（2026-09-24）

基础战术卡是制作／发布的原材料。在 AI Lab“实验设置”打开“基础战术卡库”，点击“添加战术卡”会新建一张独立的空白基础卡草稿并直接进入编辑；它不会自动加入行为组。编辑后点击“保存源”，返回卡库可单独“发布”。手动测试只选择**角色测试库**或**共用测试库**中的已配置单卡；通过“从基础卡创建”或在基础卡编辑页“另存卡”生成独立工作副本。源事件、时间轴、条件、动作 ID、费用等元数据和封装依赖全部随单卡保存，同基础可有多个不同配置版本。

点击“保存”才更新项目测试库；共用卡保存后供所有角色后续使用，未保存草稿按测试卡＋当前角色在本机隔离。测试当前修改、摘要重建和退出恢复都不隐式更新库版本。项目库在 `Authoring/RuntimeAiLab/TestCards/`，不会修改正式拥有、初始默认动作或基础卡源。

测试库初始为空，不自动迁移基础卡。空库显示创建入口；已有卡时优先恢复当前角色上次选择，否则先角色库、再共用库。原基础卡库入口继续提供制作和发布，行为组仍从基础库添加原始行为卡。操作和验收见[测试卡库说明](../Tasks/CHARACTER_CONFIGURED_TEST_CARD_LIBRARIES.md)。本节更新优先于下文历史步骤中直接测试基础卡的描述。

测试卡库现在采用可配置卡面：名称旁“改名”支持回车确认、Esc 取消；直接点击动作名称换绑，多动作可展开。“保存”提交所属库，“编辑行为”打开条件、参数和时间轴，“选用测试”指定下一张。卡面与完整编辑器共用恢复草稿，往返不会覆盖未保存内容。

## 当前战术卡的单角色测试

> 2026-09-20 发布入口更新：战术卡库是独立战术行为卡的正式发布入口。卡库中的草稿可直接“发布”，首次生成该卡的正式 r1，后续生成连续 revision；该事务只更新行为卡目录及卡引用的固定共享依赖，不创建、装配或升级任何行为组 revision。“发布本次修改”继续只用于显式发布当前行为组及其直接引用卡，不再作为独立战术卡的必经入口。

装配到行为组：在实验设置选择要编辑的行为组，点击“编辑”，在“添加行为卡”区域搜索并添加战术卡。这里同时列出正式卡和当前工作区的战术草稿；有对应战术草稿时优先使用草稿，多份草稿分别保留。添加草稿引用原 CardDraftId，不复制作者源、不要求先发布。已装配卡显示“已添加”，同组不重复添加；移除后可以重新添加。组草稿自动保存，测试和正式发布仍需分别执行。

顶部状态分别显示草稿保存和正式发布：修改后约 0.5 秒自动保存，期间显示“草稿待自动保存”，完成后显示“草稿已自动保存”；手动保存显示“草稿已保存”，失败显示“草稿保存失败”。“正式版本：已同步／有未发布修改／尚未发布”独立比较草稿与正式内容，自动保存不会替代发布，也不会更改正在运行的冻结测试。

实验设置页并列提供“战术卡库”和“战术卡测试”：前者直接进入列表，支持编辑、保存及发布；从列表打开编辑不会自动进入测试模式，返回列表仍保留发布入口。

点击“战术卡测试”，沿用当前所选角色及战场配置，先进入角色／共用测试卡列表，保持暂停。优先高亮该角色上次选择的测试单卡；否则先选角色测试库，再选共用库，不自动打开编辑页。两库为空时显示创建入口，不借用基础卡。卡面“编辑行为”打开作者编辑页，“选用测试”进入测试视图；选卡本身不执行，点击“出牌并播放”才准备并执行当前修改。从测试单卡编辑页点击“测试当前修改”进入单卡测试流程；基础卡编辑页会先要求创建测试单卡。

每次出牌只执行当前卡一次，保留原启用条件及资源检查。条件不满足时战场继续推进，显示“等待启用条件”；运行器提交整卡结束及清理后，在该帧边界暂停整个战场，等待“选择下一张”。可再次选择同一张，不能仅靠继续播放自动重打。执行中可以暂停／继续；当前卡未结束时不能换卡。界面显示待出牌／正在执行／已暂停状态。

当前独立地点、定点牵引及记录／返回点机制试用卡尚未接入意图编排，不进入行为卡工作区。测试卡面显示原因并禁用“编辑行为”和“选用测试”；入口也按实际作者源拒绝打开，避免恢复／直接调用误入。原卡源、测试库及恢复草稿保留，不转换成意图行为卡。

第一张通过原保存、编译和基线创建事务启动；后续出牌在暂停的最新帧准备并安装下一帧使用的冻结版本，记录原有版本应用历史，保留世界、角色位置、血量和敌人状态。“重新开始”才重置整个战场并停在待出牌状态。总帧上限仍来自实验设置，达到上限后需重新开始。

单卡制作页与测试后的单卡工作区继续支持空格播放／暂停。没有待出牌卡时不会推进新的战斗帧；历史帧仍可查看。输入框获得焦点或弹窗打开时不触发快捷键。

其他角色使用各自配置的运行行为组，即使与选中角色配置了相同组，也不接收这个临时候选。测试组不写回角色正式装配、不进入发布目录；候选携带明确队伍与槽位，首次安装和后续应用都只针对该角色。工作副本仍按原保存事务保存，正式组编辑／发布与普通行为卡测试保留原流程。

## 测试失败反馈

启动成功后的页面由原启动事务负责恢复，命令层不再追加“切到编辑逻辑／否则切到运行轨迹”的导航，也不按新会话默认索引打开普通卡。从战术卡制作页启动继续使用保留制作上下文的单卡测试事务；设置页的普通开始测试保留其战场入口语义，不自动打开行为卡编辑器。

从制作页发起“开始”与“测试当前修改”均使用保存并保留当前页面上下文的测试事务；失败不自动打开第一张卡或猜测的修复卡。设置页直接启动失败则留在原设置上下文。Console 的 `[Runtime AI Lab][TestStartFailed]` 记录显式请求的拒绝或最终失败，包含操作、失败阶段／代码、工作副本、角色槽位、卡身份及完整原因；逐帧可用性查询不输出这类日志。运行成功但页面定位恢复失败单独记录 `[TestPageRestoreFailed]`，不混称启动失败。

## 基础移动能力与可复用封装（2026-09-30）

在卡制作页的“封装”菜单直接选择已有共享封装加入，插入对其稳定定义 ID 的引用。菜单不提供“移动预设”创建入口，也不会每次加入都生成一份新定义。“＋ 新建空白封装”仍用于手工制作；已有封装需要分叉时使用“另存独立封装”。底层编辑器继续允许添加移动事件并选择移动方式。

选中移动事件后按方式显示目标、距离来源、速度倍率、左右方向、径向修正与持续帧数。移动目标可为当前战斗目标、世界位置 X/Z 或指定单位；单位编号 0 沿用稳定选择队友规则。位置移动是平面引导，不承诺自动绕过所有障碍。移动目标与转向事件独立；更换移动目标不会偷偷改动转向事件。

| 方式 | 行为与参数 |
| --- | --- |
| 接近目标 | 靠近至停止距离；关联动作最佳距离时沿用原最佳点接近与停止容差 |
| 保持距离 | 过远靠近、过近后退，距离带内暂停移动；目标再次离开距离带会恢复调整 |
| 远离目标 | 持续背离目标，不内置危险识别；用持续帧数或显式条件结束 |
| 横向移动 | 底层移动方式保留兼容；相关现成封装与战术卡已删除 |
| 过近后撤 | 低于触发距离时后撤，达到距离后暂停移动 |
| 环绕目标 | 横移并修正到距离带；自动／左／右，径向修正强度 0～4，默认 0.65 |

退至期望距离封装（2026-09-30）：已登记为可复用共享定义 `tactical.shared.retreat-to-distance`；在“封装”菜单直接选择“常规移动面向目标退至期望距离”加入。其 v4 EventBlock 名称为“常规移动面向目标退至期望距离”，描述为“面向目标，以常规移动后撤至期望距离。”。块内并行 `RetreatWhenClose` 移动与 `TurnToTarget`，完成规则为 `Arrived`，默认距离 1.5 米、上限 120 个模拟帧（60Hz 下 ≤ 2 秒），制作长度可配置，最小 1 帧。距离大于等于阈值立即成功并释放本段控制；开始时已满足也立即成功，不等待、不重复后撤；目标失效或超时结束当前组合并显示原因。底层持续移动策略保留供自由编排使用，现有卡未使用旧预设，因此不迁移其它卡或发布历史。创建共享定义必须保留 v3/v4 事件段版本，不能降为旧事件集合。

## 正式两层制作

1. 在 AI Lab 配置页打开“基础战术卡库”，点击“添加战术卡”进入新卡制作；已有基础卡从卡库点击“编辑”。新卡默认是空白顺序编排，不装配到当前行为组。也可以在行为组卡片制作页使用“攻击模板”创建带攻击封装的新卡并加入该组；当前顺序布局不显示旧“空白战术卡”按钮。卡名称可修改；说明由实际编排、共享内容和有效装配自动生成。
2. 中央编排区从左到右读取，显式组用括号标出。点击“添加”可新建空白共享封装并引用、引用已有封装，或加入顺序组、条件组、等待及整卡退出。卡层条目宽度不表示帧数。
3. “编排操作…”提供同组移动、成组／解组、入口／等待条件、局部结束条件、删除、撤销／重做和引用修复。Ctrl 点击可多选同级连续项成组；带条件的组需先明确移除条件再解组。条件为假时跳过，需等待时使用明确的等待组；局部结束只结束对应范围。
4. 选中引用并“展开内部”，核对共享封装名称、版本及“卡名／第几组／第几项”的影响范围。点击“确认共享修改”后，内部事件、动作槽、条件和时间关联直接写共享定义。单次引用的外层条件写当前卡；没有隐式实例覆盖。

当前制作页可直接选中上方封装，点击右侧“编辑内容”。中央时间轴随即切换为该封装的可编辑源事件，标题显示“编辑封装 · 局部帧”；可以拖动事件修改时间，或拖动普通持续事件的右边缘调整结束位置。右侧事件分组提供开始帧、结束帧、事件锚点与偏移、优先级，以及原有移动参数、动作槽和条件。动作事件的结束帧仍由动作时长推导，单帧事件不允许手填结束。修改经过原共享编辑事务，自动更新预览，撤销／重做和保存继续有效；“完成编辑”返回整卡预览。共享影响可在“编辑内容／完成编辑”的提示中查看，只希望修改当前引用时先“另存独立封装”。
5. “另存卡”保留共享引用；“另存封装并替换当前引用”创建独立定义，只替换所选引用。“替换这次使用的封装／修复引用”可重新选择定义，保留引用身份。
6. “说明详情”提供完整说明与警告的滚动阅读。“保存源”使用原工作副本持久化；“测试当前修改”保存、校验并从新基线运行。当前修改与本轮冻结版本是否一致以顶部同步状态为准。
7. “编排操作…”中的运行来源定位，以及冻结视图的“历史定位…”，可从当前等待、动作、移动、转向或最近触发定位到原引用／内部事件或卡层条件。菜单持有打开时的帧和冻结来源；源版本只读，不用当前草稿重算旧时间。
8. “返回当前制作”恢复最新帧及当前源。仍存在且未换定义的引用／事件保留定位；来源已经改变则明确返回卡层。再次修改共享内部前需确认当前影响。卡启用、单项／组条件及内部事件条件各自写回原所有者。

在“编辑封装”模式下，单击命名事件段只选中它，Inspector 显示该段属性。拖动事件段**右边缘**修改当前引用的“本次制作长度”，下限为该段最小持续帧；内部规则及后续时间引用随预览重新求值。松开提交一次，Esc 取消，支持撤销／重做；共享定义的默认长度和其他引用不变。进入内部底层时间轴需点击 Inspector 的“编辑编译结果”，单击事件段不会进入。

> 后续设计（2026-09-23，尚未实施）：见[封装底层时间轴可视化编辑方案](../../StorySource/玩法基石/任务/任务04_封装底层时间轴可视化编辑方案.md)及[预期效果图](../../StorySource/玩法基石/任务/任务04_封装时间轴效果图/index.html)。新方案增加 M／E 锚点、固定帧差／比例关联及未装配动作槽 60 帧占位；本节描述的既有 v3 能力不等于这些新能力已交付。

在制作视图选择封装并进入“编辑内容”后，源事件右侧有“编辑编译结果”。打开时只改变查看范围：中央从该项的局部 0 帧显示真实执行表中对应的事件，顶部显示“卡片 → 封装 → 当前项”。首次提交修改才创建命名事件段并升级该共享源到 v3；原事件 ID、条件、动作槽及兼容引用保留。返回封装后显示为一个整体，事件段开始仍可在外层设置。

局部视图支持右键在插入帧添加事件、在所选事件之后添加、替换事件类型、删除、拖动和缩放。替换或添加角色动作先选择动作槽，取消菜单不修改源。拖动引用时间修改偏移，引用目标保留；手填时间可选择本段帧或所属时间轴帧。时间来源可以引用事件或事件段的开始／结束，动作还提供前摇结束和动作结束。选中事件显示时间依赖连线，范围外来源显示可点击标签，也可以右键属性里的来源按钮跳转。移动距离继续支持手填、动作有效距离带和动作最佳距离，并显示当前解析值；编辑不会自动解除动作关联。

v3 正文使用 `mx.character-test.tactical-card-source.v3` / version 3。每条 timeline 可附带 `eventBlocks`，每项保存 `blockId`、`title`、`start` 和 `eventIds`。事件仍在原 `events` 中，每个事件最多属于一个块，块不能嵌套。时间引用的 `space` 为 `Timeline`（旧数据默认）或 `Block`；`targetKind` 为 `Event`（默认）或 `Block`。Block 坐标只用于成员的手填时间；锚点先在所属 Timeline 求值，再按查看范围换算显示。段结束取成员结束最大值，空段结束等于起点。编译器统一检查缺失目标、重复成员、循环、跨 Timeline 引用及成员早于段起点等错误。

编译仍生成原执行表，不创建嵌套执行器；等待和通道仲裁沿用所属 Timeline 的语义。信号和动作／移动条件引用具体成员事件。删除或替换导致引用不兼容时显示诊断，不猜测替代来源；草稿可保存，测试／发布须先修复。v2 与已有事件集合继续读取，打开旧内容不自动升级；发布和历史冻结保存对应版本的源与执行身份。修改共享源仍影响其全部引用，只改一次使用应先另存独立封装。

当前“撤步还击”通过工作副本事务建立 `block.retreat`：接近和等待的开始引用该段结束，攻击开始引用等待结束；接近和转向结束沿用原动作锚点。移动方式、距离来源与其它旧卡不由此迁移改变。

## 出手提交失败与后继配置

选卡只查询动作资格，不扣费、不预留资源、不启动冷却。真正出手时由动作使用、Ability 和正式属性拥有者协调提交：当前要求及费用提交成功后才发布动作输出；失败不产生这次动作、费用或新冷却。失败结果是这次进入的 `CommitFailed`，停留在原游标不会自动重试；需要等待或重试时明确配置。

选择攻击封装引用或顺序组，在“编排操作…”中选择“动作提交失败时结束此范围…”，再选择范围内实际动作事件。该操作写当前卡的局部结束条件，使用明确的引用／事件身份；不会修改共享内部，也不会生成隐藏实例覆盖。随后可在“编辑持续局部结束条件”中组合其它条件。整卡启用条件继续只判断启动前可用的事实，不能引用本轮执行结果。

若攻击范围后面配置了后撤封装，提交失败后可在同一世界帧移交后撤的移动／转向输入；仍受已有动作权限、运动加速度和转向规则约束。已有前向速度时先开始刹车，不能把输入移交描述成瞬间消除惯性。未配置失败退出时继续原编排，不自动退卡或指定兜底。自动说明和冻结历史描述实际配置，使用“尝试”表达动作及后继，不保证出招或后撤一定成功。

## 保存、正式发布与恢复

“保存源”保存卡编排及共享定义；“测试当前修改”先保存，再校验并冻结新测试版本。保存失败保留源和原测试，修复后重新点击测试。

发布独立战术行为卡时，在主工作区打开“基础战术卡库”，找到对应草稿并点击“发布”。首次发布沿用草稿预留的 Stable ID 生成 r1；已有来源的草稿生成下一条连续 revision。发布内容是该卡作者源及其引用共享定义的固定快照；动作槽在正式使用时按实际角色解析。本机动作摘要、当前角色执行表和任何行为组 revision 都不会写入或升级。成功后卡库状态更新为“源版本 rN”，当前测试仍保持启动时冻结版本。

只有需要同时提交当前行为组装配变化时，才返回行为组页点击“发布本次修改”。该入口会发布当前组及其直接引用的变化卡，并生成新的行为组 revision；它不是独立战术卡发布入口。

独立卡发布失败时，卡片内显示具体编译、引用、来源冲突或目录写入原因，草稿保持不变。组级聚合发布失败则按其确认界面结果处理：

- 已确认未提交或完整回滚：保留草稿，修复后重新预览。
- “已提交，等待恢复”：保留已确认版本，点击“核对目录并恢复”，补齐草稿检查点和实验配置。
- “提交状态待核实”：先复读目录核对，不能把目标 revision 当成已确认版本。

恢复期间顶部显示“恢复发布”；重复确认不再次写入。恢复记录位于项目 `UserSettings/RuntimeAiLab/PublishRecovery`，编辑器重开后仍可核对；恢复本身不新增 revision，完成后清理记录。后续作者修改保留在工作副本中。

正常 Game View 的验收尺寸为 1920×1080 与 1366×768；布局、弹窗、输入和流程的对应关系见[验收对照](../../StorySource/玩法基石/任务/任务04_M4_验收对照.md)。独立 Editor 试用窗口不是本指南的正式制作入口。

## 兼容 v2 作者源与内部编辑基础

新 schema 为 `mx.character-test.tactical-card-source.v2`。普通 v11 行为卡保持原入口，不能把新源文件放进旧 v11 payload 后直接发布。

[完整样例](../../StorySource/玩法基石/任务/任务04作者源样例/README.md)包括默认单段卡、删除接近、结束关联 +4f、显式退出及断动作引用。模板仅执行一次；普通编译直接使用实际事件、条件、槽位与关联，不重新生成模板。

当前内部入口：

- `CharacterTestTacticalAuthoringJson`：严格读写和源语义身份。格式未知／重复字段／不规范 JSON 拒绝；可读的断引用错误源保留供修复。
- `CharacterTestTacticalAuthoringTemplates`：空白／默认模板和严格 version 1 导入。
- `CharacterTestTacticalAuthoringCompiler`：作者校验、端点关联、原条件树及动作数据绑定，直接生成任务 02 执行表；编译结果带角色、装配、动作、摘要来源、依赖身份及事件来源。
- `CharacterTestTacticalCardBinding.TryCompileAuthoring / TryAcquireAuthoring / TryValidateAuthoringRestore`：沿用同一绑定 owner；执行中拒绝覆盖，当前无效装配拒绝旧产物启动，恢复检查实际依赖。

以上是项目内部低频准备入口，不是新的 Runtime Tick 解释器或公开 SDK。当前支持五种前端事件：CharacterAction、ApproachOptimalRange、TurnToTarget、WaitForCondition、ReturnToPlanner；普通卡其它合法事件仍由普通编辑器保持。

## AI Lab 中查看作者源

1. 进入现有 AI Lab 的“编辑逻辑”，在预览右上角点击“导入战术源”，选择上述 v2 JSON。导入新增一张当前组工作副本卡，不转换或覆盖原普通卡；选择文件期间工作副本版本变化会拒绝提交。
2. 在左侧当前组列表选择新卡。事件来自该卡保存的作者源；右侧显示所选事件的开始／结束关联、动作槽、关联动作、优先级及当前角色求值结果。普通卡继续使用原编辑器。
3. 输入未准备或编译失败时，源条目仍可选择。界面隐藏求值标尺，并明确提示条目位置不是执行时间；不会恢复模板或把旧运行计划当作新源。
4. “摘要准备”打开面向当前实际角色、起手动作、装备和测量规格的 Editor 窗口。当前入口明确使用标准靶 v1、50mm 步长、0～5m 范围；不把验证巨型靶摘要冒充标准靶。
5. 重建完成后点击“返回 AI Lab 原卡制作”，再“重新查询”和“测试当前修改”。当前源按实际 providers 重新准备、编译并冻结新测试；保存、模式切换和返回位置的实际证据见执行记录第二十一章。

源编辑通过独立事务写回同一工作副本，旧 Recipe 写入命令仍会被拒绝，显示投影不能覆盖作者源。当前修改测试已接入；预览编译通过不代表源已发布或测试世界已更新，正式发布和恢复通过顶部当前组入口执行，状态与证据见执行记录第二十一章。v2 仍使用对应 payloadSchema 读取和保存，允许保留可读取的断引用错误源。

## 创建与制作操作

- 当前“空白战术卡／攻击模板”按上节创建 composition。通过兼容入口导入的旧 v2 卡仍直接拥有内部源，旧 v2 的“另存新卡”复制其内部事件与关联；此语义不应混同于新卡保留共享引用的另存操作。
- 点击事件后，在右侧修改名称、优先级、速度、开始／结束的绝对帧或关联偏移。事件锚点可以选择来源事件及 Start／End／ActionStartupEnd／ActionEnd；“定位关联事件”会选择来源并调整可见范围。
- 动作事件通过“动作槽”选择源中的槽引用，不写入当前解析出的动作编号。动作结束由正式动作时长决定，不能手工修改；“打开动作制作入口”复用原角色动作制作工具。
- 点击空白时间轴区域可修改时间轴名称、顺序和入口。这里的 Event.priority、Timeline.order 是制作数据，不是玩家可以调整的选卡优先级或装配顺序。
- 制作 Inspector 以封装为单位，按作者源顺序列出全部事件，默认展开、可分别折叠。事件条件直接嵌入各自区域：Gate 显示“等待放行条件”，动作显示“动作起手条件”，显式退出显示“退出条件”。整卡启用条件仍由卡级入口编辑。继续先选判断对象，再选事实；逻辑组支持 All／Any／Not 和动作数据条件，“动作距离／动作朝向／动作机会 → attack”保留来源选择，不把绑定改为字面值。
- 制作 Inspector 不显示开始帧、结束帧、端点关联和事件优先级；已有源数据保留。点击时间轴事件只展开、定位对应事件区域，不切换为单事件 Inspector。顶部“编辑内容”直接进入共享编辑；“另存独立封装”另行处理独立引用。
- 条件编辑时右栏临时使用520单位宽度，中央区域同步收窄；退出后恢复普通三栏。字段输入按 Enter 或普通离开输入框时提交，Esc取消；直接切换卡或共享引用时取消未提交文本，避免切换前隐含写入旧对象。输入焦点开始时保存编辑身份与版本，过期编辑拒绝写入。
- Ctrl点击进行多选，拖动按帧吸附。拖动期间只更新派生预览，松开提交一次；Esc、失去焦点、移除或调整宿主时取消。已随选中锚点移动的引用不再重复增加偏移；不允许跨时间轴部分移动或批量调整单个结束边界。
- “删除选择”先展示可滚动的关联影响，再次确认才删除。其它事件与断引用保留，之后可以改关联或撤销。撤销／重做复用工作副本历史。
- 点击竖向命令栏“保存源”。该入口使用现有工作副本持久化；保存错误不会进入测试验证／重启。保存成功不等于发布成功。

## 独立 Editor 摘要入口

Unity EditMode 菜单：

`MxFramework → CharacterTest → Tactical Metrics → Prepare Character Opener Summary`

1. 选择正式角色及明确的测试动作。测量请求必须携带所选动作 ID；不再从角色基础 ActionSet 的 LightAttack 映射推导战术动作。
2. 选择测量规格：标准人形靶，或明确标为验证用途的巨型偏移靶。
3. 点击“查询当前装配摘要”。Missing／Stale 不自动重测。
4. 点击“显式重建当前装配摘要”。重建后重新 Query；失败不回退旧摘要。
5. 查看输入与诊断详情，确认角色、动作、装配和规格；后续回到正式制作入口后需要重新编译并开始新轮，本操作本身不启动测试。

窗口可以接收 AI Lab 捕获的稳定准备请求。从制作界面的“摘要准备”打开后，可点击“保存制作内容并退出运行”；保存失败时保持运行。退出后显式重建，再点击“返回 AI Lab 原卡制作”，恢复原工作副本、卡和引用位置，重新编译并开始新测试。窗口使用“默认装备”时保留 spawn 已解析的真实默认装配，不用空 stable key 覆盖它。

内部 `CharacterTestTacticalSummaryPreparation.TryDescribe` 从实际 source/providers 捕获角色、装备、正式起手、内容身份与规格；`TryRebuild` 使用隔离 ProbeSession、原测量器及原 Store。重新准备的输入不匹配原请求时拒绝覆盖。请求不持有跨场景的 Unity 实例引用。

默认派生缓存为 `Library/MxFramework/CharacterActionTacticalMetrics`；它可以重建，不提交为作者资产，也不直接作为正式发布卡内容。缓存按角色／动作命名，测量规格参与有效性校验，因此更换规格可能使之前的摘要失效，需要明确重建。

## 支持范围与证据

### 整卡行为卡时间轴

**生命周期说明（2026-09-09修正）**：卡被使用后由执行器读取 `EntryTimeline` 进入实际首段；末段到达边界后由执行器自然结束，调度层随后释放当前卡。编译器不生成通用启动事件、正常退出事件或末段到空出口的跳转。列表中剩余的进入时间轴操作用于实际内部衔接／条件跳转，显式退出操作来自明确配置；它们不是每张卡的必需首尾事件。旧冻结产物如仍带历史中转，只作为旧版本事实显示，不代表当前规范。

左侧卡片栏底部提供“制作视图／底层时间轴”切换。“底层时间轴”在当前页面复用原版行为配方时间轴、命令栏和Recipe／Timeline／Event属性检查器，直接读取整卡实际执行表；保留多条Timeline，不按封装重新排列或拼接。动作编号、时钟、次数、冷却、移动参数、条件树及跳转目标来自编译产物。编译扩展谓词按真实类型显示，不套用作者格式中不适用的校验。该模式为只读，切回“制作视图”后继续编辑作者源。重新开始测试后保留所选模式。

以下说明适用于“制作视图”中的来源投影；它不再代替原版底层视图。

制作页中央、战斗预览上方，显示整张卡当前编译产物中的底层时间轴和事件。包含作者事件及编排所需的内部衔接、条件跳转、等待和配置的局部结束；不把整卡进入与自然结束画成事件。上方选中封装只高亮并定位对应来源，不隐藏其它封装。

每条底层时间轴都从自身进入时的0帧起算，标题标注来源和“局部帧”。Gate停留多久、条件是否成立、局部结束何时发生由运行决定，不能把这个视图当成已确定的战斗总时长。向下滚动可查看后续时间轴，横向滚动／缩放查看帧范围。

点击作者事件会依据编译来源映射定位对应封装引用和事件，右侧仍编辑原作者源；点击“编辑内容”后，中央显示所选封装的源时间轴，拖动、添加事件和属性编辑均写原作者源并重新编译整卡。“完成编辑”后恢复整卡执行表。同一共享封装重复装入时，引用身份分别保留；所选引用的动作装配参与内部预览。底层编译表继续只读，编译器生成的控制事件显示只读详情，条件来源仍使用原条件编辑器。

冻结历史源保留对应的整卡执行产物；当前编译失败或冻结执行数据不可用时显示诊断，不把旧产物或局部编译成功冒充当前整卡结果。

### 预览镜头操作

制作页预览右上角的模式按钮显示当前模式，点击循环切换：自由观察 → 第三人称跟随 → 多角色自动取景。默认使用多角色自动取景；放大预览后仍可切换模式，返回不重置选择。

- **自由观察**：保留切入时视角；滚轮缩放，右键／中键拖动平移，Shift + 右键拖动旋转。在自动模式中操作这些手势会切到自由观察，并同步按钮文字。
- **第三人称跟随**：以当前选中 Agent 为主角，有当前目标时使用已有锁定目标构图器组织视角，再由框架 Follow 镜头驱动。无目标时保持单角色固定方向跟随；不是玩家输入驱动的第三人称控制器。
- **多角色自动取景**：收集当前选中运行帧中具备几何数据的 Agent 及其目标，按实体去重，交给框架 GroupFollowPerspective；不能据此声称自动发现所有场景 GameObject。视口安全距离同时考虑宽高比和预览身体范围。
- **适配视野**：自动模式重新求值；自由模式执行一次框选，仍保持自由模式。重新进入自动模式请点击模式按钮。

预览持有独立的 Camera Unity Rig，仅修改自身相机；不发送角色操作或正式镜头模式命令。历史帧取景读取当前展示帧的数据，不读取最新世界 Transform。无可用角色时保留视角，自动模式在数据恢复后继续取景。

此处复用框架取景及第三人称构图能力，但不挂接正式玩家输入、移动参考系、镜头震动或遮挡控制。预览快照目前只有中心点，没有完整作者骨骼锚点和身体包围盒；采用预览身体范围做安全适配，不声称与正式角色专属镜头配置逐像素一致。

单段动作及空间摘要沿用[任务03支持范围](CHARACTER_TEST_TACTICAL_CARD.md)和[动作摘要指南](CHARACTER_ACTION_TACTICAL_METRICS.md)。不支持的动作、NoHit／不连续或开放区间等不会因为点击重建就变成有效首卡。

双装配夹具明确使用角色 000001／301 和 000003／940000，巨型偏移参考靶为版本2、高5000mm、半径2200mm、中心(0,2500,-4000)mm、100mm步长、[0,10000]mm搜索。当前测试验证 +4f 的移动右边界分别23／41、动作右边界77／121；这些不是标准人形靶射程。

专项检查、真实控件、输入路径、保存／发布往返与故障恢复证据统一记录在任务04执行记录。适用范围限定为现有 AI Lab、受支持的单段动作及两层编排，不扩展通用脚本语言、生产摘要分发或新的玩家卡组系统。

### 摘要缓存格式更新

战术摘要缓存使用 `.bin`。旧 JSON 不再读取，需使用“重建所选摘要”或“全量重建摘要”重新测量；新二进制写入且校验成功后，仅清理对应旧 JSON。批量报告仍可读，角色持有数据、动作作者源和冻结源不因缓存格式变化而修改。

## AI Lab 运行时重建摘要（2026-09-24）

在动作选择器点“重建所选摘要”或“全量重建摘要”，保持 Unity 播放和当前卡库／编辑页。任务使用当前角色和装备的独立无视图模拟，轨迹按模拟 Tick、距离按采样点分步推进；每次 UI Update 最多推进四步，并检查约 4ms 预算（一次采样或会话初始化不可拆分）。不会推进、重置或改写当前战场，也不会改卡片绑定、正式持有数据或冻结版本。

在 AI Lab 战术卡测试中选用测试卡时，若该卡绑定动作的摘要缺失或因测量输入变化过期，会按需启动同一分帧重建任务。重建期间点击出牌会保留这次请求；成功后重新校验整卡并自动继续，失败或角色、装备、卡片修改时取消自动出牌并显示原因。有效摘要直接使用，不重复测量；武器轨迹缺帧时不尝试摘要重建，等待 Editor 烘焙更新后再次选卡。此自动准备只适用于 AI Lab 测试入口，不进入战斗逐帧执行或 Player 构建。

Unity Editor 在动作库、角色动画目录、武器配置／模型或已引用动画片段导入变化时，按受影响角色包排队自动烘焙武器轨迹；同一输入指纹不重复烘焙，生成的轨迹目录不会反过来触发新任务。队列保存在本机 `Library/`，Unity 重开后继续。烘焙只在 Editor 空闲的 Edit Mode 进行；Play Mode 中发生的修改留待退出播放后处理，以免刷新正式资源时打断当前战场。失败会在 Console 写明角色包和首个原因，不覆盖失败前的烘焙产物。完成后再次进入 AI Lab 选卡，摘要按前述流程自动重建。

- 顶部显示当前动作、采样进度及成功／失败／跳过数量；运行中“全量重建摘要”变为“取消重建”。
- 单项完成后写入现有二进制摘要缓存并自动刷新可选状态，保持搜索、筛选、所选动作及列表位置。
- 取消、关闭动作选择器、禁用 Lab 控制器、切换角色／装备或动作源变化会停止未完成任务。当前未完成动作不提交，已经成功完成的动作保留；失败不覆盖旧缓存。
- 当前测量器仍只支持攻击类型。闪避无需空间摘要；其它类型明确跳过。缺失资源、动作结构不支持、无有效命中等错误显示具体原因，不伪造可用摘要。
- 完成或取消后输出可读 JSON 到 `Library/MxFramework/CharacterActionTacticalMetrics/BatchReports/runtime-*.json`；悬停进度文字可查看逐项结果与报告路径。

Unity 编辑器菜单里的离线准备窗口继续可用，但运行时按钮不再调用退出播放／保存返回书签的流程。以上覆盖本文较早的运行时重建退出播放说明。

## 等待条件（2026-10-01，r2；原等待战机）

分配边界：进入等待且捕获非空窗口集合时，分配一次窗口 ID 数组；稳定逐帧观察不分配。快照 Clone/Copy 根据目标容量复制数组，不能将整段执行宣称为零分配。

`等待条件` 是独立基础意图，描述为“等待指定条件成立后，继续后续行为”。作者模板仍为 `CreateWaitOpportunityDefinition()`，共享身份仍为 `tactical.shared.wait-opportunity`、修订 r2，内部使用 v4 作者源和既有 `WaitForCondition`。共享定义通过工作区 owner 编辑/保存事务升级；添加菜单仍读取该工作区真实共享定义，不额外维护一套菜单目录。注册共享定义不安装卡到角色组、不发布、不写玩家持有存档。

- 进入本段时捕获当前目标、当前真实动作实例及已经生效的 HitTraceWindow ID 集合。只等这些窗口全部退出；后续新动作或同动作的新窗口不延长本次等待。此规则不推断前摇后的未来攻击，不观察飞行中弹体的命中时间。
- 等待只阻塞卡片进入下一段；等待期间不追加移动、转向、攻击或防御指令。进入时提交一次带 owner/source 身份的释放命令，撤销此前该执行器残留的移动/转向输入；不重置物理速度、不停止已有动作，不清除独立技能请求。已有动作、惯性、外力、受击仍按原系统规则处理。外部接管后的输入不被旧 owner 的释放覆盖。开始无有效窗口时捕获空集合，仍跨最短一个世界帧边界结束，不等待下一次攻击。
- 目标缺失、死亡或切换独立返回 `TargetMissing`；观察端口或完整帧不可用返回 `ConditionRejected`。攻击被打断导致捕获窗口实际退出，可正常成功；不依赖动画名字或估计时长。
- 等待上限默认 60 帧，编辑 v4 EventBlock 的 `Timing.DurationFrames`，或使用已有引用实例 `BlockDurations`。卡面显示“最多等待”，时间轴长度表示上限，条件满足可提前结束。最小预算固定 1 帧，不是可延长的等待下限。
- `completion=Condition`、`completionEventId=wait`、`requireLivingTarget=true`。成功条件可通过现有条件编辑器修改，但不能绕过捕获窗口结束屏障；捕获窗口事实只能在所属等待封装内部使用，不能变成整卡准入或 DSL 外部条件的预知信号。自定义条件超出标准形状时，描述退回通用条件说明，不继续显示不准确的模板文案。
- 先检查目标有效，再检查捕获窗口及配置条件，最后检查独立上限；恰好边界帧满足则成功。超时为 `TimedOut`，本段不自动追加攻击或其他事件；后续行为由卡的显式编排决定。
