# Sword blade trail presentation contract

> Status: Guide
> Document revision: 2026-10-09

This is presentation only. Damage, hit windows, attack admission, equipment defaults, weapon trace bake catalogs and tactical numbers retain their existing authority. All existing weapon hit windows now enable the linked trail, including actions 460–463; Action Hit Volume windows remain independent.

The stable resource is `vfx.weapon.blade_trail:GameObject@mxframework.samples`, resolved by the existing Resource Manager. `CharacterTestSceneProfile.BladeTrailVfxPrefab` supplies the prefab to the existing memory provider/catalog. The prefab has `UnityBladeTrailBackend`, MeshFilter and MeshRenderer, one transparent URP material, and no `UnityVfxLifecycleController`, ParticleSystem or TrailRenderer. ## Authored event

The default authoring entry is now the single weapon's `presentationConfiguration.bladeTrailResourceKey` and `bladeTrailResidueMilliseconds`, plus the `HitTraceWindow.bladeTrail` settings. CharacterStudio offers **默认拖尾样式** on the weapon. New weapon hit windows created in Character Action Authoring, including the timeline context menu, default to **启用武器拖尾**. Select the window to disable it or set **拖尾提前帧** / **拖尾延后帧** (both default to 0). Empty weapon style or unarmed equipment produces no automatic trail.

`bladeTrail` contains `enabled`, `advanceFrames`, `delayFrames`, and a prepared `stableEventId` from event domain 401. The existing identity catalog allocates this identity when the user creates a weapon hit window or explicitly enables an association. Loading a document does not allocate identities or override an explicit disabled setting. Offsets extend only the visual window; combat frames and damage retain their authority. Derivation clamps the visual window to 0 through `durationFrames - 1`.

The compiler and Editor share `CharacterActionBladeTrailJsonProjection`. It derives one `SpawnVisualCue` per enabled window with `bladeTrailGenerated=true`, `bladeTrailSourceEventId`, and the explicit `useWeaponBladeTrailStyle` flag. Source save removes these derived events and retains the hit-window settings. Repeated generation is idempotent; disabling/removing a window deletes only its owned generated event. Manual events, including identical-resource events, are preserved; a stable-identity collision blocks generation instead of deleting the manual event. Generated events remain visible but read-only in the timeline/Inspector. Parameter 2 stays reserved; it does not select automatic styling.

Runtime and preview resolve the style and residue from the actual weapon selected by the existing trace/slot authority. Explicit traces for another slot are refused for automatic presentation. A style must be a registered VFX GameObject using the blade-trail backend and must follow the existing VFX resource publication workflow. An unavailable definition skips playback with a runtime diagnostic; this configuration entry does not publish a new prefab by itself.

CharacterTest character loading materializes missing weapon trace endpoint transforms from the imported geometry's declared locator paths and poses after the equipment binder spawns each weapon, matching the action preview. Existing model locators are preserved. Lookup uses the spawned weapon's numeric weapon/slot identity, so a failed earlier equipment binding cannot shift another weapon's endpoints. Socket-relative poses are converted into the spawned weapon's local space; no guessed blade geometry is introduced.

The existing-window update enables all 15 weapon hit windows in the Common library. Existing linked identities and offsets are preserved: action 455 retains event ID 391 and visual 18–38 by using +6/+6 around hit 24–32. Actions 457/458 retain their independent manual cues as well as their new linked trails. Action Hit Volume windows are excluded. Each new association receives its own event identity through the authoring catalog.

Weapon defaults are emitted into `WeaponConfig.BladeTrailResourceKey` / `BladeTrailResidueMilliseconds` / `BladeTrailStyleId` and included in the compiler source hash; linked action settings remain part of the existing action-source hash. Existing CharacterAction player JSON mirroring, package generation and R-domain content receipts carry these optional fields. Recompile/export both the character package and action JSON after changing defaults/settings, then use the existing Player artifact validation; old player mirrors cannot be accepted as current evidence.

## Configurable types and dynamic overrides

CharacterStudio's single-weapon **表现配置** exposes **默认拖尾资源** and **默认拖尾类型**. `presentationConfiguration.bladeTrailStyleId` is optional: 0 preserves the resource's material preset, 1 is thin blade light, 2 is a soft ribbon, 3 is double blade light, and 4 is an energy trail. All types reuse the same published blade-trail resource, actual blade sampling, lifetime and pool budgets. Existing weapon files without this field keep their current appearance.

CharacterTest exposes `GameManager.TrySetWeaponBladeTrailStyleOverride(entityId, equipmentSlotId, WeaponBladeTrailStyle)` and `ClearWeaponBladeTrailStyleOverride(entityId, equipmentSlotId)`. An override applies immediately to active and fading ribbons for that actor/slot and to subsequent hit windows. Clearing it restores the configured weapon default. Missing actors, invalid slots and unsupported types are rejected; stale actor identities cannot transfer an override to a replacement actor. These are local presentation overrides, held in the presentation binding scope. They do not change action data, equipment versions, VFX request parameters, combat state or replay/network authority.

The backend's `ConfigureStyle(int)` applies a cached, per-renderer material property block; shared materials are not modified and pooled views reset to their material preset. The style selector does not repurpose reserved VFX parameter 2. Timeline preview reads the same weapon default, and the compiler fingerprints the authored type while retaining the same hit geometry.

This entrance change has project-external offline evidence only until it passes coordinated Unity compile/preview/runtime acceptance. It does not resolve or accept the separate ordinary-ParticleSystem `Complete` native validation failure.

Use the existing `SpawnVisualCue` event with `StopAtEventEnd` and `Dissipate`. The event stable identity and action instance identify its Enter/Exit pair. Initial candidate emission windows are 455:18–38, 457:30–48 and 458:8–38 at the existing timeline FPS; these are visual windows, independently adjustable after native viewing. They are deliberately wider than the hit windows and do not read the partial hit-window bake as full visual motion.

The existing four integer VFX parameters are interpreted for this resource only:

| Parameter | Contract |
|---|---|
| 0 | Required numeric equipment slot. Uses the formal `mainHand` equipment slot ID 1; socket ID 12 is a separate identity and must not be supplied here. |
| 1 | Optional explicit trace ID; 0 uses existing slot-first trace resolver. |

| 3 | Residue milliseconds, 80–150. 0 uses the authored prefab default 100 ms; invalid nonzero values are rejected by publication validation. |

Definition ID 12080 is published. Future serial publishing must check the latest catalog for collision before importing. Do not assign IDs from old snapshots or reuse an event's numeric identity by name without the existing compiler preparing it.

## Pose and continuity

The existing `CharacterWeaponTraceBindingResolver` resolves the formal equipment slot, weapon ID and root/tip locator paths. The equipment binder records the binding of each *successful* spawn; failed earlier slots cannot shift the pairing. Runtime and timeline preview require this actual spawned weapon and both locator Transforms. Missing/unarmed equipment, missing locators, an unavailable resource or a replaced action produces no sword geometry and does not alter combat or default equipment. No fallback hand socket, guessed object name or disk path substitutes for the blade.

At the end of character presentation, the backend reads the currently displayed root/tip world positions, including current presentation pose adjustments. History remains in world coordinates; applying a new VFX anchor never drags the old ribbon with the owner. The ribbon has two vertices per blade pair, one layer and per-point age alpha. Default opacity is 0.22 and emission history duration is 0.10 s. The sample material uses subdued additive pale-white light, a narrow soft core on the blade-tip path, a transparent root and a feathered historical tail. The newest end stays visible so the trail connects to the current blade, and the tip feather is confined to the outermost 0.3 percent of the blade span. Age alpha comes from the backend without a second shader age multiplier. Material controls expose tint, glow strength, root fade and arc width without changing hit geometry.

Intermediate samples evaluate the matching current clip at its actual clip times through `IMxAnimationPoseSamplingBackend`; they do not linearly interpolate blade endpoints. Animation graph time, Animator event policy and cached transform local poses are restored; sampling does not call animation Tick, action Tick or alter authority. Current crossfade weights are retained. Interpolated owner position/rotation only supplies the between-frame basis. Historical procedural corrections and historical blend weights are not recovered by this method; final endpoints come from the actual presented pose. Native tests must verify animation/root-motion continuity around sampling, especially during crossfade and procedural correction.

Default limits are 32 retained pairs, 16 intermediate steps, 200 Hz target sample spacing and 8 emitting-or-retiring ribbons per presentation scope. Runtime maximums are 64 pairs, 16 steps and 32 leases. Arrays and mesh storage initialize once; steady Tick creates no temporary collections. If a frame would exceed its bounded sample budget, sampling is unavailable, action time rewinds, action instance/equipment changes or the owner teleports more than 1.5 m, old geometry is disconnected/cleared instead of inventing a chord through an unknown spin. A newly admitted action gets its own source. A source that loses its matching action or actual weapon stops emission and fades existing world-space history.

## Lifetime, preview and cameras

`IUnityVfxTimedBackend` is an optional extension to existing backends. `UnityVfxPresenter.TickPresentationBackends` supplies one presentation clock after character pose presentation; it never runs from per-camera rendering callbacks. Complete/Dissipate stops emission and keeps the view in the presenter's existing retiring collection. The sample prefab opts into `_exitFadeSeconds=0.25`: its final world-space silhouette and current sample-age alpha are retained while a smooth global opacity curve fades it to zero, then the pool receives the cleared view. No new samples are taken during this tail. The optional field defaults to zero for other blade-trail prefabs, preserving per-sample expiry. Immediate, restore, disposal and pool rebinding clear mesh, source and lease. Scope disposal destroys its mesh. Other VFX backends retain their existing behavior.

The action timeline preview uses the same backend, sample limits and budget. Its existing action Enter/Exit metadata identifies trail views; Exit stops emission and retirement continues across the event end. Seek backwards, action replacement and preview hierarchy replacement clear old views through existing preview cleanup. Preview uses the current bound animation backend or its existing fallback graph and restores sampled transforms. No game assembly dependency is introduced into the framework editor.
