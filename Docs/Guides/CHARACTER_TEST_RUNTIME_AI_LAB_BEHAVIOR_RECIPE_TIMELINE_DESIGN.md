## CharacterAction 引用编辑

- Event 操作为“播放角色动作”时，作者通过正式的可搜索动作选择器选择 `CharacterActionConfigRegistry` 中的稳定动作引用，不填写裸 `CharacterActionId`。
- 选择器显示动作名称、稳定 ID、分类与权威时长；搜索覆盖名称、ID、分类和标签。
- 行为卡可被多个行为组和角色共享，因此选择器显示完整动作目录，不按当前测试角色隐藏条目；角色当下能否执行仍由动作 Requirement 和运行结果判定。
- 时间轴显示动作名称，保存与运行身份仍使用稳定 ID。缺失或失效引用保留原 ID并阻止保存、运行和发布，不静默替换。

## 设计结论

编辑器只呈现行为配方、并列 Timeline 和统一 Event。Timeline 各自从局部 `0f` 开始并共享同一比例尺；Track 不命名、不显示、不保存，纵向 lane 只负责避免 Event 重叠。自动布局按开始帧、优先级和稳定 EventId 排序，使用半开时间区间执行确定性的 first-fit：互不重叠的 Event 复用最低可用 lane，只有时间区间重叠时才增加 lane。拖动或调整宽度提交后会重新紧凑排布，lane 变化不修改行为数据、语义哈希或运行顺序。

Event 显式分为两种时间类别，不能通过拉伸互相转换：

- 单帧事件：只在指定帧采样一次，用 `2px` 帧针和固定宽度浮层卡片表达；没有右边缘。
- 持续事件：在固定半开区间内逐帧采样，用真实 Span 表达；右边缘是持续角色操作的硬终止边界。

时间类别与 Operation 独立。单帧 Move 或 CharacterAction 启动后按操作自身生命周期继续运行；持续版本到右边缘仍未结束时会被取消。需要停住或重复游标时，作者显式使用“等待条件”或“循环区间”。行为配方不提供 Ability Event；需要技能动作时选择该 Ability 绑定的正式 CharacterAction。

## 共享行为卡与行为组边界

- 行为卡是按稳定 `StableCardId` 管理的共享定义；同一工作区中只保留一份可编辑草稿。
- 行为组只保存安装记录和组内配置：`EntryId`、行为卡稳定引用、职责集合、启用状态与显示/仲裁顺序。它不拥有行为卡内容副本。
- 从任意行为组进入同一张行为卡并修改 Timeline/Event，会修改共享行为卡；工作区内其他引用该卡的行为组立即看到相同内容，行为组 revision 不因此变化。
- 添加、删除、禁用行为或调整职责属于行为组修改，不会让行为卡“保存”按钮变亮；行为卡语义修改也不会把行为组标记为已修改。
- “保存”针对当前选中的共享行为卡草稿；“保存行为组”只追加行为组版本；“发布行为版本”只追加行为卡正式版本。
- 正式行为组中旧 revision/hash 仅作为来源审计。新实验按稳定卡身份解析最新兼容正式版本；进入运行后仍冻结不可变快照，避免运行中热变更。
- 从旧工作区恢复时，历史上由 Copy-on-Write 产生的组内卡片副本会按稳定身份合并；优先保留 revision 较高的编辑版本，并把全部组引用重定向到该共享定义。

## 选择和 Inspector

任务04三栏布局复用本节定义的原事件与属性控件。时间轴保留本地左侧120单位命令栏；中央预览与时间轴分隔条改变高度时，重新计算事件裁剪、标尺和滚动区域，不重新构建作者源。Inspector按可用宽度排布控件，保持字体尺寸。正式包与实现状态见[布局与预览接入基线](../../StorySource/玩法基石/任务/任务04_T4-3_布局与预览接入基线.md)。

任务04用户确认的[v5制作界面](../../StorySource/玩法基石/任务/任务04_UI重制新效果图/v5_设计说明.md)新增独立布局分支：紧凑顺序编排在上、所选封装内部事件在中、中央战斗预览在下，右侧Inspector全高。命令复用外侧竖列，内部时间轴从本地x=0开始，不重复绘制120单位命令栏或独立标题；普通行为卡仍沿用原分支。整卡条件在左侧复用正式条件列表并有独立写入上下文，事件条件仍写对应内部源。当前实现与实际验证见[UI重制执行记录](../../StorySource/玩法基石/任务/任务04_UI重制执行记录.md)。

- 点击行为配方标题：编辑行为启用条件。
- 点击 Timeline 空白：取消 Event 选择并编辑 Timeline 名称、入口身份和进入条件。
- 点击 Event：编辑该 Event。
- 删除 Event 后返回所属 Timeline；Timeline 消失后返回行为配方。
- v11 编辑逻辑不回退到旧 Stage/Detector/Transition Inspector。

条件编辑器先选择判断对象，再从属性类别选择一个具体条件。首期对象只有目标、自身、环境；其中“目标”固定指 Runtime AI Planner 的锁定目标，内部稳定标识仍为 `CurrentCombatTarget`。Event 额外允许引用其他事件结果。属性类别仅用于导航，不要求每类选择，也不进入权威数据。每个 SubjectScope 显示为对象卡片；对象卡内可连续添加同对象属性，逻辑组通过独立“+ 逻辑组”入口维护。

目标属性目录保留“目标状态 / 目标根节点平面距离 / 目标 Hurtbox 表面距离 / 距离下一攻击窗口剩余帧”。根节点距离用于稳定的整体空间关系；Hurtbox 表面距离读取当前 RuntimeFrame 中自身姿态胶囊到稳定锁定 Hurtbox 的三维表面净空，不替代具体招式的 Attack Opportunity。目标状态弹窗多选允许阶段，并为六个正交状态显式选择“不限 / 必须 / 排除”；选择只修改本地草稿，“应用”才作为一个 Undo 事务提交，“取消”和点击外部不修改权威数据。选择过程中弹窗保持打开。

目标不存在时，目标作用域整体显示“不可用”，不能把 0 米或 false 当作有效采样；位于作用域外且允许 `NoTarget` 的目标状态可正常满足。无会话显示“未采样”；Review 读取 selected RuntimeFrame，不得泄漏 Latest。Inspector 展示当前阶段、当前状态位以及阶段不匹配、缺少必须状态或命中排除状态的具体原因。

Event Inspector 不显示开始帧输入，也不显示旧的“固定/直到离开时间轴”。开始帧由卡片横坐标表达；时间类别必须显式选择。

```text
时间类别：[单帧事件 / 持续事件]
当：组合条件树
则：操作和参数
持续事件：时长 [30] 帧 / 次数 [1] / 冷却 [0] 帧
单帧事件：不显示时长、次数和冷却
优先级：[数值]
运行：[真实运行状态]
```

拖动主体修改 StartFrame；只有持续事件可以拖动右边缘修改 DurationFrames。切换时间类别是一次显式 mutation；若当前 Operation 不兼容，确认后在同一 Undo 事务中清为“未配置”。

## 时间控制 Event

### 等待条件

- 使用统一 Event 组件和统一条件树。
- 固定 `1f` Marker，可水平拖动，不可调整宽度。
- 条件未满足时，局部游标固定在该帧；条件满足后继续。
- 空条件显示“永久等待”。
- 运行时显示“正在等待条件”。

### 循环区间

- 使用统一 Event Span；左右边缘直接表达循环范围。
- 条件树表达“退出条件”，空条件表示不按条件退出。
- “最多重复 0 次”表示无限；N 表示初次通过后最多额外回绕 N 次。
- 卡片主体可移动，右边缘可调整循环终点。
- 普通 Event 可以跨越循环边界。完全位于循环内的 Event 随回绕进入下一 pass；跨越边界的 Event 保持 Timeline 级执行状态和角色控制权，退出循环后继续到自身右边缘。
- 运行时显示当前重复次数，不绘制伪 Tween 回绕动画。

## Timeline 末端

整卡进入由调用方启动执行器，执行器直接读取 `EntryTimeline` 初始化实际入口和游标。内部 `EnterTimeline()` 方法不是事件；不需要一条启动跳转来进入卡。

Timeline末端是执行结构中的边界，不是退出事件。没有等待、循环或显式跳转改变流程时，执行器采样前检测 `LocalFrame >= DurationFrames`，调用停止／清理流程，完成后报告 `Completed`；空Timeline在首次采样时完成。AI Lab调度层观察终态并释放当前卡，再按既有调度规则决定后续。

编译器对末段使用实际正常边界，不增加一帧来跳往空出口；对有实际后继的中间段可以生成顺序衔接跳转。条件为假的末尾If分支、无后继的空Wait在放行后都自然结束，不生成通用退出事件。显式配置的退出、条件跳转或局部结束保留；最终范围的局部结束条件命中时可以生成显式退出操作。`ReturnToPlanner` 的界面名称为“显式退出行为卡”，不表示由事件执行Planner选择。

最右端细终点线不占lane、不可选择。结束和动作清理由已有执行器负责，不播放额外打断动作；不能通过仅隐藏系统中转行来宣称编译结构已修正。

## 真实运行游标

游标只读取所选测试角色、运行槽位和不可变行为快照中的真实 `TimelineId / LocalPlayheadFrame / authority hash`：

- `2px` 亮青实线，只贯穿当前 Timeline 的自动 lane。
- 等待时帧号保持不变；Loop 回绕时下一 RuntimeFrame 直接出现在循环起点。
- 暂停时冻结；历史查看读取同一历史快照；证据不足时隐藏。
- 编辑卡未运行、运行旧草稿、角色不一致或 authority 不匹配时隐藏。
- 当前 Timeline、Event 运行描边和 Inspector 状态使用同一份运行身份。
- 游标不可点击、不可拖动，不承担 Seek，也不拦截 Event、右键或滚轮。

默认自动跟随；手动横移、缩放或滚动后关闭跟随，“适配可见时间”重新启用。关闭跟随且游标离开视口时完全隐藏，不吸附边缘。

## 视觉规则

- 单帧事件：精确帧针加浮层卡片，卡片宽度只用于可读和命中，不代表时间。
- 持续事件：始终是具有真实左右边缘的 Span；即使只有 `1f` 也不会变成单帧类别。
- 等待条件：紧凑阻挡 Marker。
- 循环区间：低强度回绕提示 Span。
- 不存在 Open Span 或 `∞` 尾部。
- 视觉宽度很小时保留真实帧宽，只扩大透明命中区，不伪造时间范围。
- 选中使用白色外框；真实运行使用青色描边；迁移待确认使用红色虚线诊断。
- 添加、删除、移动或调整 Event 宽度后自动重新计算紧凑 lane；互不重叠的 Event 可以同处一行，重叠 Event 必须分行。布局变化不改变任何 Event 的高度、圆角和内部布局。

## “持续接敌”正式表达

```text
Timeline：持续靠近

[0f────────30f] 接近目标
[0f────────30f] 循环区间
退出条件：
  任一满足
  ├─ 目标距离 ≤ 1.5 米
  └─ 可用移动路径 = 否
最多重复：无限
```

游标在 `0..29f` 采样；条件不满足时回到 `0f`，满足时离开循环并到达 `30f`，随后 Timeline 完成并返回行为决策。系统不会自动加入“目标不存在”，作者需要时自行添加。

## 保存与迁移反馈

旧开放 Event 迁移后显示“此事件原为开放区间，请确认固定长度”，并以红色虚线阻断运行。作者可以先拖动右边缘，再通过 Inspector 或右键菜单确认当前区间；确认与撤销均保持 EventId 和选择。

v7 内容按操作语义迁移：Wait 为单帧，Loop 为持续，Move/CharacterAction 保持持续；跳转、返回和未配置操作按旧时长 `1f` 或多帧映射。旧 Ability/Hold Event 保留身份用于诊断，但阻止保存、运行和发布；Ability 必须改为其绑定的 CharacterAction，固定空等待应删除或改成明确条件等待。runtime contract 4 / snapshot 9 的活动状态不得直接恢复为 v8。

“保存”只在语义变化且 v8 校验通过时启用。未配置 Operation、非法时间类别或类别与 Operation 不兼容时只保留内存编辑，不写入可运行草稿。保存后用新不可变快照从测试第 0 帧重模拟到保存前 RuntimeFrame；正式发布独立。播放头和运行高亮只接受真实运行 TimelineId/EventId/authority hash。
## 角色动作事件

`CharacterAction` 不再是普通条件 Event 的可选操作。作者必须通过时间轴右键菜单的“添加角色动作事件”进入正式动作目录；取消选择不会留下占位 Event。创建后的动作事件是不可缩放的固定片段：左边缘为启动帧，宽度和右边缘来自所选 CharacterAction 的权威帧长，更换动作或动作目录时长变化后自动同步。动作事件不允许条件、次数或冷却；旧带条件动作 Event 必须由作者显式移除条件后才能运行。

选中角色动作事件后，Inspector 提供“查看动作时间轴”入口。Player 继续打开只读 `CharacterActionWorkstation` 投影；Unity Editor 不跳转独立全屏页，而是在当前 AI Lab 页面保留 Game 渲染帧，将下方行为时间轴原地切换为完整 CharacterAction 七轨，并将右侧 Inspector 切换为动作或所选条目属性。动作模式左侧只显示原行为 Timeline、Event 与动作 Stable ID 的紧凑来源卡，不继续展示完整行为库；右侧 Inspector 使用“基础 / 时间 / 需求 / 当前片段”分组，并在选择时间轴条目时自动切换到当前片段。该当前页模式继续提供 Undo/Redo、校验、Save All 和当前测试角色草稿预览；动作目录与 Problems 作为按需入口，不常驻抢占 Game 渲染区域。动作正文仍不嵌入行为配方数据；正式保存只写 Common 或角色包动作源，并经过角色包导入、CharacterTest 热重载和测试第 0 帧重启后生效。
