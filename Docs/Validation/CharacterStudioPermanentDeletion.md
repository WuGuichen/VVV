## 角色自有登记清理

共享文件前后哈希及记录身份纳入计划哈希；执行时再次校验，并以同目录临时文件原子替换各个共享 JSON。清理失败停止角色文件删除，报告已清理项和剩余项，编号仍保持退休；重新检查可继续。非空战术配置、未知生产者/版本、其他登记中的真实依赖仍阻塞。

## 引用检查耗时修复

用户检查 `000005` 时报告长时间等待。原路径性能采样为 57.4 秒，其中约 44 秒花在通用 32 位十六进制正则扫描：大型特效 Prefab 中的内嵌网格数据被无差别扫描，界面只显示固定文字。

现优先使用 PATH 上的 `rg` 对目标角色 ID 和拥有的 GUID 做两次原生字面量预筛选，仅对候选文件执行原有精确引用判断。预筛选包含隐藏和被忽略的文件；不缩小原目录/扩展名范围。所有原有链接检查保留，扫描异常失败关闭；无 `rg` 时回退为精确 GUID 字面量查找，不再枚举所有十六进制候选。相对目录按目录计算，避免逐文件重复解析。

- 删除工具测试现为 9 项通过：新增原生/回退完整计划一致、被忽略及隐藏引用不遗漏、GUID 子串不误报、原生扫描错误不放行。
- 真实 HTTP 临时项目的 3 项删除测试与前端确认测试仍通过。
- 实际网页检查 `000005` 用时 5.471 秒，仍准确列出 global_resource_mapping_profile 与 tactical_acquisition 两处引用，未发送删除请求。
- 检查期间显示已等待秒数；浏览器验证观察到 1 秒反馈，结果返回后停止计时。性能数字为本机本次测量，不是跨机器时限保证。
